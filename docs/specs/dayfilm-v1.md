# Dayfilm v1 功能规格

本规格是 Dayfilm 预期行为的权威来源。产品目标见[产品说明](../product/dayfilm.md)，实现结构见[架构文档](../architecture/dayfilm.md)。

## 平台与运行

- 目标平台：Windows 10/11 x64 桌面。
- 单实例运行；重复启动时聚焦已有窗口。
- 不要求管理员权限，不写系统目录，全部数据位于 `%APPDATA%\dayfilm`。
- 离线可用；运行期不发起任何网络请求。

## 术语

采样、镜头、剪辑、中场休息、胶片、题材的定义见[产品说明](../product/dayfilm.md#核心概念)。

## 功能需求

### R1 采样

1. 程序启动后每 2 秒采集一次当前前台窗口：进程名、窗口标题、距最后一次输入的空闲毫秒数。
2. 采集失败（无前台窗口、进程已退出、脚本不可用）时不得崩溃，继续下一轮采样，并通过实时状态暴露 `captureError`。
3. Dayfilm 自身窗口获得焦点时，采样照常落盘，但不计入胶片、汇总与检索；胶片上该时段表现为空隙。
4. 空闲毫秒数 >= 60000 时视为空闲。

### R2 落盘

1. 采样按本地日期写入 `%APPDATA%\dayfilm\days\YYYY-MM-DD.jsonl`，每行一个采样 JSON。
2. 进程正常退出时，已采集的采样不丢失；异常退出最多丢失最后 2 秒。
3. 历史日文件只追加，不覆盖既有内容。

### R3 镜头切分

1. 相邻两次采样满足"同进程同标题"且间隔 <= 90 秒时，归入同一镜头。
2. 镜头时长 >= 3 秒才输出；更短的瞬态切换并入相邻镜头之间的空隙，不单独成镜。
3. 空闲持续的区间输出为 `kind: 'intermission'` 的中场休息镜头。
4. 镜头按开始时间排序，序号从 1 开始稳定递增（同一天内同一份采样集合重算得到相同结果）。
5. 采样时刻 `t` 由主进程在收到采样行时打点；镜头 `end` 向后延伸一格采样（约 2 秒）并夹紧到下一条采样或当前时刻，因此"3 秒成镜"实际至少需要 2 条同窗口采样。中场休息不延伸，`end` 停在区间内最后一次空闲采样。

### R4 当日胶片

1. 主界面展示当天 00:00 至当前时刻的胶片，横轴按时间比例铺开。
2. 每个镜头显示进程名、标题、时长；悬停或选中时展示起止时间。
3. 胶片必须能区分镜头、中场休息两种状态。
4. 当天无数据时显示空状态，说明"还没有拍摄任何素材"。

### R5 实时状态

1. 界面每 2 秒收到一次实时状态，包含正在拍摄的镜头、采集是否工作、当日汇总。
2. 顶部显示"正在拍摄：<进程名> <标题>"或"空闲中"。
3. 采集进程异常退出后，界面在 10 秒内显示采集错误提示。

### R6 当日汇总与题材

1. 汇总包含：活跃时长、空闲时长、镜头数、剪辑次数、最长镜头、进程时长排行前 5。
2. 剪辑次数 = 相邻两个非空闲镜头之间的切换次数。
3. 剪辑密度 = 剪辑次数 / 活跃小时数；题材按密度划分：< 3 长镜头，[3, 8) 标准剪辑，[8, 20] 快切，> 20 跳切风暴。
4. 题材附一句中文点评，说明当日最长的镜头或最碎的片段。

### R7 检索

1. 输入关键词（检索前去除首尾空白），对最近 7 天（含当天）的镜头标题与进程名做不区分大小写的子串匹配。
2. 结果按开始时间倒序，跨日期合并后截断到 200 条，每条可点击定位到胶片上的对应位置。
3. 空查询返回空结果，不做全量输出。

### R8 历史

1. 提供日期切换，列出所有存在数据的日期，默认当天。
2. 切到历史日期时展示该日的完整胶片与汇总。

### R9 导出剧本

1. 可将指定日期导出为 Markdown 剧本，写入用户选择的路径。
2. 剧本文本包含标题行、每个镜头一行（时间、进程、标题、时长）与当日题材结论；分钟数四舍五入且正数下限 1 分钟。用户取消保存时返回空路径，不写文件。

## MVP 范围裁剪

第一里程碑只要求 R1–R9 在正常路径下可用，且允许以下简化：

- 镜头切分与汇总在每次刷新时全量重算，不做增量索引。
- 仅在 Dayfilm 运行期间采样，无开机自启。
- 无窗口标题脱敏、无保留期清理、无加密。
- 无安装包，使用 `npm run dev` / `npm start` 启动。

## 可交付版本追加要求

- **安全与隐私**：标题脱敏规则、保留期与清理、渲染进程隔离校验、IPC 入参校验、导出路径约束。
- **健壮性**：崩溃恢复、跨天切日、休眠唤醒、采集进程自恢复、异常退出不写坏数据。
- **性能**：单日 5 万采样、30 天历史下的启动与交互指标，空闲 CPU 与常驻内存上限。
- **验证**：单元测试、集成测试、压力测试及其结果记录。

具体指标与验证方式在第二里程碑的设计中确定并登记到本规格。

## 验收

MVP 验收以本规格 R1–R9 的正常路径逐条核对，核对方式记录在 `docs/operations/mvp-verification.md`。
