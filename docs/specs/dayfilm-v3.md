# Dayfilm v3 功能规格：故事线候选、剪辑发现、找回某一幕、模型通道

本规格定义 v3.0 的三项确定性能力与一条可选的模型通道。方向裁决见 `docs/delegate/ai-proposal.md`、`docs/delegate/gpt-answer-9.md`，选型见 [ADR 0005](../agents/adr/0005-model-channel.md)。

## 范围与总原则

- 三项能力**不依赖模型**也能独立交付；模型只是第 4 节的一条可选增补，默认关闭。
- **模型不出现在渲染路径上**：同一份数据任何时候渲染结果一致。模型只在用户点按钮时被调用，结果作为可确认的草稿出现，确认后写进 `settings.projects` 才生效。
- 所有候选与发现**必须带证据**：每条输出都能指回具体镜头（日期 + 开始时刻）。
- 界面文案不出现「AI」字样；模型设置区标题是「模型通道」。

## S1 故事线候选

### S1.1 入口与形态

设置抽屉「项目」分区里有「找候选」按钮。点击后列出候选，每行：

```text
login    12 个镜头 · 1 小时 12 分
         例：fix-login-bug.ts · dayfilm - Visual Studio Code
                         [ 添加为项目 ]
```

- 点「添加为项目」才写入 `settings.projects`，规则名取候选词本身，关键词取该候选词；写完后按现有 `matchProject()` 口径生效。
- 候选为空时不显示列表，只显示「最近 30 天没有发现可归并的候选」。
- 候选区始终可关闭；不写任何自动规则，不在后台运行。

### S1.2 候选口径（纯函数，确定性）

输入：`DayRollup[]`（最近 N 天，默认 30，按主进程 `DayCache` 读取）+ 现有 `ProjectRule[]`。

1. **标题归一化**（`normalizeTitle`）：去掉尾部 ` - <应用名>` / ` — … ` / ` | … ` / ` · … ` 后缀；去掉开头未读数 `(3)` 与标题内 `(3)`；去掉 Windows 路径前缀；全角转半角；`*` 与 `•` 脏标记去掉；折叠空格。归一化只用于候选抽取与检索召回，**不改写落盘原文**。
2. **实体抽取**（`extractEntities`）：按非字母数字切词后保留：
   - 含 `.` 的文件名取主干（`login.spec.ts` → `login`）；
   - issue 前缀（`DF-412` → `DF`）；
   - 长度 ≥ 3 的拉丁词 / 长度 ≥ 2 的中文词；
   - 排除：进程名自身、常见噪声词（见 `NOISE_WORDS`：`index`、`readme`、`github`、`the`、`and` 等）。
3. **统计与门槛**：同一实体按镜头计数与去重时长累计。进入候选需要
   - 命中 ≥ 5 个不同镜头，且累计 ≥ 10 分钟；
   - 命中 ≥ 2 个不同日期，或 ≥ 3 个不同进程；
   - 未命中现有任一 `projects` 规则的关键词（避免重复建议）。
4. **归并**：若两个实体互为子串（`day` / `dayfilm`），保留命中更多的一方；归一化后大小写不敏感。
5. **排序**：镜头数降序 → 时长降序 → 名称字典序（保证同输入同输出）。
6. 最多返回 8 条。

### S1.3 降级

- 采样不足（没有日文件）→ 空数组，不报错。
- 读盘异常 → 空数组，界面显示「读取最近 30 天失败」。
- 历史日读取受 `DayCache` LRU 限制；候选计算最多触碰 30 天，不做全量驻留。

## S2 剪辑发现

### S2.1 入口与形态

hero 区题材与点评下方新增一行「剪辑发现」（最多 3 条），每条一行：

```text
↩ 重返主线  上午的 login 在 15:20 又出现了，中间隔了 4 小时 12 分
```

- 每条可点：定位到证据中最早的那个镜头（当天视图内滚动并选中）。
- 当天没有发现时不占位、不显示标题。
- 不做通知、不打分、不出现「专注」「效率」「建议」等评价词。

### S2.2 检出规则（纯函数 `findDiscoveries`，只读 `DayRollup`）

按优先级取前 3 条，每条附 `evidence: number[]`（镜头开始时刻，1–3 个）：

| 类型 | 判据 | 文案骨架（不出现评价词） |
| --- | --- | --- |
| `return` 重返主线 | 同一实体（S1.2 抽取结果）出现在两个相隔 ≥ 90 分钟的镜头里，且中间至少有 2 个其它镜头 | `上午的 X 在 HH:MM 又出现了，中间隔了 N 分钟` |
| `switch` 主线易位 | 按 `matchProject()`（无项目时按进程）统计，上午与下午的首要对象不同，且两者都 ≥ 20 分钟 | `上午的主线是 X，14:00 之后换成 Y` |
| `revisit` 反复打开 | 同一归一化标题在一天里出现 ≥ 4 次，且总时长 ≥ 15 分钟 | `同一个窗口今天打开了 4 次，共 22 分钟` |
| `late` 深夜镜头 | 20:00 之后开始的镜头里，有一段 ≥ 30 分钟 | `20:00 之后还有一段 47 分钟的镜头` |

- 同一实体只出一条（`return` 优先于 `revisit`）。
- 全部为 shot 镜头；中场休息不参与。
- 时间格式用界面已有的 `HH:MM`。

### S2.3 降级

- 单个镜头的一天：只有 `late` 可能命中；没有就整块隐藏。
- 任何规则抛出/越界 → 该条丢弃，保留其余。

## S3 找回某一幕（检索增强）

### S3.1 行为

现有搜索框不变，`dayfilm:search` 的匹配与排序升级：

1. **查询归一化**：与 `normalizeTitle` 同一套（全角→半角、去脏标记、小写）。
2. **分词**：按空白与常见分隔符切成词；中文短语不切（按整词子串匹配）。
3. **时间词**（从查询里剥离，不当作标题词）：`今天`、`昨天`、`前天`、`本周`、`上周`、`这周`、`上上周`、`上周一`…`上周日`、`YYYY-MM-DD`、`M月D日`。解析为日期集合，命中后只在这些日期里检索；解析不出来就当普通词。
4. **匹配**：所有词都命中（`title` 或 `exe` 的归一化文本包含该词，或该词是实体词的子串）才算命中；否则不返回。
5. **排序**：命中词数降序 → 开始时刻降序 → 日期降序。最多 200 条。
6. 空查询返回空数组；非字符串返回空数组。

### S3.2 边界

- 时间词单独出现（如只输入「昨天」）→ 返回该日全部镜头（按时间倒序），属于合法查询。
- 未知日期（`2月30日`）→ 当作普通词处理。
- 检索覆盖范围不变：今天 + 最近 7 天（`SEARCH_DAYS`）。

## S4 模型通道

### S4.1 设置

设置抽屉「模型」分区：

| 字段 | 类型 | 默认 | 约束 |
| --- | --- | --- | --- |
| `ai.enabled` | boolean | `false` | 打开后才会发请求 |
| `ai.baseUrl` | string | `''` | 必须是 `http:` / `https:` 绝对地址，最长 512；空串表示不启用 |
| `ai.model` | string | `''` | trim，最长 64；空串表示不启用 |
| `ai.apiKey` | string | `''` | trim，最长 256；本地服务可留空 |

- 三个字段任一为空（`apiKey` 除外）时按钮禁用。
- 打开 `ai.enabled` 时，面板内明示**会发送什么**：「会把最近 N 天的窗口标题、进程名与时长发给 `ai.baseUrl`。数据会离开这台机器。」
- `apiKey` 以明文存 `settings.json`（与 coding agent 的配置文件同一口径）；文档与界面都写明这一点。

### S4.2 调用

- 复用成熟库 `openai`（官方 SDK，OpenAI 兼容端点），不自己实现传输与重试；调用 `chat.completions.create`，`temperature: 0.2`，`signal` 超时 20 秒。
- Prompt 只喂聚合摘要：`{date, exe, title, minutes}` 数组（最多 200 条，标题已过 `redactSample`）+ 现有项目名；要求返回 JSON。
- 输出校验：解析 JSON 的 `stories: [{name, terms}]`；`name` 1–32 字、`terms` 1–5 个、每个 1–32 字；非法整条丢弃；与现有项目重名的丢弃。
- 结果作为**候选**并入 S1 列表，标注来源 `model`；用户点「添加为项目」才落盘。

### S4.3 降级与失败

| 情况 | 行为 |
| --- | --- |
| 未启用 / 字段不全 | 不显示模型入口 |
| 请求失败、超时、4xx/5xx | 保留确定性候选；面板状态行写明「模型不可用：<原因类型>」，不弹窗 |
| 输出不合 schema | 丢弃该次模型结果，保留确定性候选，状态行写明「模型返回格式不符」 |
| 连续失败 2 次 | 本次会话不再自动发起，只有用户再点按钮才试 |

- 请求只由用户点按钮触发；启动、采样、渲染路径上没有任何网络调用。
- 主进程侧只允许 `http(s)` 且必须与 `ai.baseUrl` 完全一致的 host；不做重定向跟随（SDK 默认不跟随跨域重定向），日志只记错误类型，不记标题与 key。

### S4.4 安全

- 渲染层 CSP 不变；网络调用只在主进程。
- `ai.apiKey` 不写日志、不回显到界面（界面只显示「已设置 / 未设置」与「清除」按钮）。
- 关闭 `ai.enabled` 后不再发起任何请求。

## 验收

1. 纯函数：`suggest.test.ts`（归一化、抽取、门槛、归并、排序）、`discover.test.ts`（四类检出与上限）、`reel.test.ts` 检索（多词 AND、时间词、排序）在同一份 fixture 上重复运行输出一致。
2. IPC：`ipc.test.ts` 覆盖三个新通道（`suggest-stories` / `ai-stories` / `ai-probe`）与入参校验。
3. 设置：`settings.test.ts` 覆盖 `ai` 字段归一（非法 URL、超长 key、空 model）。
4. 降级：模型缺失时 `ai-stories` 仍返回确定性候选，`source: 'template'`。
5. 手工：真实 30 天数据上点「找候选」，确认接受一条规则后周视图主线随之改变；拒绝/删除后回到旧主线。
6. 网络：默认设置下启动、采样、翻日、放映全程无出站请求（`installNetworkGuard` 之外再加代码评审确认 `src/main/ai` 是唯一网络出口）。
