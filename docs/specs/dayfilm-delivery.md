# Dayfilm 可交付版本要求

第二里程碑的范围与验收口径。产品目标见[产品说明](../product/dayfilm.md)，MVP 行为见[Dayfilm v1 功能规格](dayfilm-v1.md)。

## 定位变化

MVP 只在窗口开着时采样，实际连续性不足。可交付版本按"安静的常驻程序"补齐：托盘常驻、开机自启可选、关闭窗口默认收到托盘而不是退出。

## R10 隐私与脱敏

1. 内置脱敏规则命中时，窗口标题替换为 `[已隐藏]`，进程名保留；命中判定基于标题与进程名的关键词（不区分大小写）。
2. 内置规则至少覆盖：密码管理器（`1password`、`keepass`、`bitwarden`、`lastpass`）、隐私浏览（`incognito`、`inprivate`、`隐私`）、网银与支付（`bank`、`银行`、`网银`、`支付`、`wallet`）。
3. 用户可维护自定义关键词列表，增删即时生效；命中自定义词的标题同样替换。
4. 脱敏在写入前完成：磁盘上不出现被隐藏的原始标题。
5. 已有历史数据不做回溯改写；设置界面注明生效时间。

## R11 数据保留

1. 默认保留 30 天，可设为 7/30/90/365 天或不自动清理。
2. 启动时清理超过保留期的日文件；清理失败不阻塞启动，但要在界面暴露。
3. 界面的日期列表只列出保留期内且存在的日期。

## R12 常驻与生命周期

1. 关闭主窗口默认隐藏到托盘并继续采样；托盘菜单提供"打开""暂停采样/继续采样""退出"。
2. 托盘悬停提示与菜单项表达当前状态（采集中/已暂停/出错，出错优先），悬停附当日已记录时长；托盘图标保持单一样式。
3. 开机自启为开关项，默认关闭；开启后写入当前用户的启动项，不要求管理员权限。
4. 真正退出时停止采集、刷新缓冲、清理子进程树。
5. 单实例；再次启动时把已有窗口带到前台。

## R13 休眠、跨天与时钟

1. 系统休眠/挂起时暂停采样，恢复后从当前时刻继续，休眠区间不伪造数据，表现为无采样空隙。
2. 跨本地零点自动切到新日文件，前一天的收尾不受影响。
3. 系统时钟回拨或大幅前跳时，丢弃倒序采样（`t` 不大于该日最后一条的记录），不污染既有镜头。丢弃只计数，不打断采集；持续丢弃时不弹窗打扰。
4. 时区变化后按新的本地日期归档，不修改历史文件名。

## R14 存储可靠性

1. 采样追加失败时进入内存缓冲并重试；连续失败要在界面暴露"写入异常"状态，不静默丢数据。
2. 读取时容忍尾部半行与坏行，不因单行损坏丢掉整天。
3. 日文件超过 64 MB 时给出提示，不自动切分（避免改变既有格式）。

## R15 安全边界

1. 渲染进程保持 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`；CSP 不允许远程脚本、远程样式、远程图片与 `eval`。
2. 主进程按通道白名单处理 IPC，校验入参类型与范围；只接受来自本应用窗口的调用。
3. 导出只写用户通过保存对话框选择的路径，扩展名固定 `.md`；写失败返回可读错误。
4. 不记录窗口标题到日志文件；错误信息只保留进程名与时间。
5. 不发起任何网络请求（可用进程级网络禁用或代码评审确认）。

## R16 性能与容量

以单日 5 万条采样、30 天历史（约 150 万条）为基准，目标：

| 指标 | 目标 |
| --- | --- |
| 冷启动到窗口可交互 | ≤ 2.0 秒 |
| 新增采样到界面更新（单日 5 万条） | ≤ 16 毫秒 |
| 切换历史日期（1 天 5 万条） | ≤ 300 毫秒 |
| 跨 7 天检索（冷，含读盘） | ≤ 800 毫秒 |
| 跨 7 天检索（热，走缓存） | ≤ 5 毫秒 |
| 空闲 CPU（窗口收进托盘、无操作） | ≤ 0.5%（占整机 16 核） |
| 常驻内存 RSS（窗口收进托盘、30 天历史） | ≤ 300 MB |
| 单日提交后界面帧率 | 不低于 50 fps（参考项，不作硬门槛） |

口径说明：空闲 CPU 与常驻内存按"窗口收进托盘"的常驻状态测量，这是产品的主要运行形态；窗口打开时的数值作为参考另记。测量方法与原始输出记录在 `docs/operations/perf-report.md`。

## R17 打包与分发

1. `npm run dist` 产出免安装的 Windows x64 可执行程序，含应用图标与 `resources/capture.ps1`。
2. 打包产物在没有 Node.js 的机器上可运行；启动后行为与开发模式一致（含数据目录、单实例、托盘）。
3. 产物不包含源码映射与测试文件。

## R18 验证要求

1. 单元测试覆盖：脱敏规则、保留期清理、时钟回拨、增量聚合与全量结果一致、坏行与半行。
2. 集成测试：用临时数据目录跑采集→落盘→切分→导出整链，不启动窗口。
3. 压力测试：脚本生成 30 天 × 5 万条采样，输出 R16 各指标实测值与设备信息，结果写入 `docs/operations/perf-report.md`。
4. 交付前由未参与实现的 Agent 做一次独立评审，发现的问题逐项处理或说明保留理由。

## 验收

逐条核对 R10–R18，实际结果与证据写入 `docs/operations/delivery-verification.md`。
