# Dayfilm v4 方向评审与裁决

评审对象：当前代码库的功能现状。问题来自用户的三点：记录内容够不够、要不要真实截图、已有数据还能怎么用（含 AI）。
输入：三份独立评委报告（[eval-data.md](eval-data.md)、[eval-screen.md](eval-screen.md)、[eval-ai.md](eval-ai.md)）+ 一次外部裁决（[gpt-answer-13.md](gpt-answer-13.md)）。
本文只记录结论与执行顺序；证据在评委报告里，不复述。

## 一句话结论

**v4 不做"记录更多"，做"读得更深"**：主题定为「故事的连续性」——用已经躺在 `days/*.jsonl` 里的关系（前一天停在哪、最长镜头之后被什么接走、休息回来有没有接上、检索的时间范围），让历史数据第一次服务于"接着昨天"。截图永久否决，AI 只保留一个带退出机制的实验。

## 三位评委的判定

### A 记录内容：偏薄，但缺口不是"更多字段"

- 4 个字段能把"谁 / 哪个文档 / 多久 / 有没有在敲"答完；`idleMs` 落到盘上却只被当成 60 秒空闲开关（`src/main/reel/index.ts` 的 `groupRuns`）。
- 答不了的四类：同一窗口里"在写还是在看"、窗口形态（全屏/分屏/第几块屏）、有没有声音、2 秒内的切换。最伤的是粒度——`cuts` 按 2 秒采样点算，系统性偏低，而"跳切风暴"这个唯一的当日结论就靠它。
- **两个现存缺陷**（不是新功能）：
  1. 锁屏/无前台窗口 → `capture.ps1` 输出 `ok:false` → 主进程记成"第 N 条采样无效" → `hudMood()` 与 `trayMood()` 双双变 `error`。**锁屏去吃午饭，HUD 在报错。**
  2. `cuts` 把"换应用"和"同应用换文档"算成同一个数（`prev.exe !== curr.exe || prev.title !== curr.title`），一个下午在三份文件间来回改会被判成跳切风暴。
- 建议先做：修上面两条；窗口矩形（`GetWindowRect` + `MonitorFromWindow`，A 级隐私、约 0.02 ms、+0.3~0.6 MB/天）留到 v4.1。任何新字段都**不得参与镜头切分**，否则 `marks.json` 按镜头开始时刻存的标记会整体错位。
- 明确不建议：键盘内容或按键计数、剪贴板、鼠标轨迹、全窗口枚举、pid/hwnd 落盘、浏览器地址栏（C 级 + 每次 10~100 ms）。

### B 截图：只做局部 → 经裁决后改为"整条砍掉"

- 三条 Windows 路径里：WGC 只能桌面捕获（Electron 的 `desktopCapturer` 映射不到 HWND、Win10 强制黄框）；DXGI 只能整屏且要常驻会话（电池）；`PrintWindow` 能进现有 PowerShell 助手，但跨进程会被 UIPI 拦。
- 成本：480×270 JPEG ≈ 20 KB，每 60 秒 480 张 = 9.6 MB/天 = 288 MB/30 天；只在切窗口时约 250 张 = 5 MB/天。CPU 都在噪声内，**真正的代价是隐私机制**：DPAPI 只防"文件被拷到别的机器/账户"、不防同用户进程；今天没有一键抹除通道；`save-image` 会把图写到用户桌面；黑名单永远追不上新应用。
- 评委原判是"只做 32×18 光签名（≤1 KB/帧，只存亮度和主色）"，并要求把产品真相从"不截屏"改写成"不保存画面"。
- 真实截图的第三个代价容易被忽略：剧照现在是纯函数产物（`still-frame.ts`："只算画什么、画多大、放在哪"），有真图后同一份数据在不同时间会渲染出不同结果，**"同一份数据渲染一致"这条当场失效**。

### C 资源 / AI：时间几何已用九成，关系不到一成；现在的模型通道是装饰品

- 时间几何（时长/剪辑/中场）≈90% 被脊柱、放映、周矩阵、EDL、PDF、海报、HUD 吃掉；标题语义只用在候选、发现、检索三处；`notes.json`（每天 ≤200 字）只在自己那一天露一次面，**从不作为任何推理输入**。
- 真正没人读的是关系：同一天里"最长那条之后被什么接走"、跨天"上次停在哪"。现有 `findDiscoveries()` 四类（return/switch/revisit/late）一条都不算这两个。
- 模型通道被自己的门槛压成装饰品：只能给 1 个关键词（`MAX_TERMS = 1`）、必须命中 ≥5 镜 / ≥10 分钟（`candidatesFrom()`）、还要和规则候选去重。4 个候选里 3 个是"规则换说法"。
- 日评语/周评语换模型不值：`judge()` 的 note 是**可核对的指认**，会进剧本、PDF、海报三处成品；模型只会更长更泛，且两次导出一致性会破。
- 值得一次网络调用的只有一处：把一天写成一句**带专有名词**的话，落进用户手记框，点一下才保存。
- 专注管理能落成三个只读形态（上一集 / 最长镜头之后 15 分钟 / 中场休息的形状）；要砍掉所有专注时长、专注分、趋势、目标、连胜、提醒——有指标就会有人为了让数字好看去改 `marks.json`，而标记是产品唯一的真实判断输入。

### 顺带发现的两处规格漂移（可直接修）

| 规格（`docs/specs/dayfilm-v3.md` S4.2） | 代码 |
| --- | --- |

## 外部裁决（ChatGPT）

完整回答见 [gpt-answer-13.md](gpt-answer-13.md)。要点：

- **v4 主线选 A（读关系）**，版本主题「故事的连续性」。理由是：窗口几何能让镜头更丰富、截图能让剧照更真实、AI 能让文字更自然，但只有关系分析能让用户得到此前不知道的东西；而且它上线当天就作用于仍在保留期内的历史数据。
- **截图：永久否决可读截图，连光签名也砍掉。** 理由一句话：「不截屏」比「截了屏但不保存」更有品牌价值。替代方案是**语义剧照**——不还原用户看见的内容，而是用真实元数据（编辑器/浏览器/终端/设计工具）决定构图，追求辨识度而不是逼真度；窗口几何留到 v4.1 参与构图。
- **AI：只赌手记草稿，并给它退出机制。** 三种文字分三种作者：规则写评语（指认发生了什么）、AI 写草稿（试着组织成一句话）、用户写手记（决定这一天意味着什么）。验收门槛（建议值，非实测）：事实准确率 100%、首次校验通过率 ≥90%、愿意直接或轻微修改后保存 ≥60%、相比规则摘要更愿意采用 ≥70%；任一项不达标只允许一次针对性调整，第二轮仍不达标就砍掉入口。同时复审现有故事线候选——如果不能稳定提供规则之外的增量价值，连模型通道一起移除。
- **专注管理先做「上一集」**：它是唯一直接帮助用户开始今天的功能，也是产品第一次让历史数据服务于下一次行动。第二条「镜头之后」建议改名——切换窗口不一定是被打断。第四条候选「惯用蒙太奇」：识别反复出现的跨应用工作序列，它可能揭示一个与直觉相反的事实——**高频剪辑不必然意味着注意力破碎，有时恰恰是一个完整的工作流程**。
- 边界：精确匹配只能说明上次出现过哪个窗口/标题，不能推断任务完成进度；检索必须区分「没有匹配记录」与「超出数据保留范围」。

## v4 执行顺序

| # | 任务 | 归属 | 备注 |
| --- | --- | --- | --- |
| 1 | 锁屏／无前台窗口误报 | 基础修复 | 缺陷，不算新功能；`away` 采样走中场休息分支，不得成镜头 |
| 2 | 跨应用／应用内剪辑拆分 | 基础修正 | 只拆计数与文案，不改题材四档边界，不声称解决 2 秒漏记 |
| 3 | 上一集（跨天续接） | v4 核心 | 精确匹配；只显示日期、时刻、原始标题、时长 |
| 4 | 镜头之后 15 分钟 | v4 核心 | 纯计数；只陈述不评价 |
| 5 | 中场休息的形状 | v4 核心 | 几点走、多久、回来是否回到原窗口 |
| 6 | 检索时间范围对齐 + 命中理由 | v4 核心 | 时间词点名哪几天就查哪几天，不再固定 7 天 |
| 7 | 窗口几何 + 语义剧照 | v4.1 | 几何不参与切分 |
| 8 | 惯用蒙太奇 | v4.2 | 序列级发现，需先有几何 |
| 9 | AI 手记草稿生死测试 | 独立实验 | 通过则留，不通过连模型通道一起砍 |

约束：v4 **不新增主导航、不新增独立分析仪表盘**；新的关系发现嵌入现有日视图、周电影与检索。

## 明确不做

- 可读截图、32×18 光签名、把缩略图发给模型接口、导出物嵌真实帧、区域模糊/马赛克、OCR 落文本。
- 模型重写 `judge()` / 周评语 / 片名 / 导演阐述，模型判断正片花絮，模型自动写手记。
- 任何专注时长/专注分/趋势/目标/连胜/番茄钟/提醒，以及"干扰源 Top 5"这种换词的榜单。
- 向量索引、聊天式问答、更高频固定采样、键盘/剪贴板/鼠标轨迹。
