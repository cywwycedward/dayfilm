## 已核实的事实

- 数据形状：`days/YYYY-MM-DD.jsonl`，每行 `{t, exe, title, idleMs}`；派生成镜头 / 剪辑 / 中场休息 / 题材 / 正片花絮标记 / 项目规则 / 剪辑发现 / 故事线候选。手记 `notes.json`（每天 ≤200 字）、标记 `marks.json`。
- 已交付的"智能"全部是模板与规则：题材只有 4 档 label + 一句 note、旁白是 5 条优先级规则拼固定句式、周评语同模板、剪辑发现是 4 条阈值规则。
- 唯一的模型通道：默认关闭，OpenAI 兼容端点，只由用户点按钮触发，只用来补充故事线候选（1 个关键词），结果要用户确认才落盘；`temperature 0.2`、60 秒超时、只喂聚合摘要（≤80 条 `{exe,title,minutes}`）。
- 硬约束：确定性渲染（同一份数据任何时候渲染一致）、默认无网络、数据只在本机、隐私优先、品牌是"剪辑台/放映室"而不是效率工具、界面文案不出现"AI"字样（用"模型通道"）。
- 历史外部裁决明确否决过：周报式、"效率管理工具"、给用户打分的 KPI 方向。**但不要把"关注度/专注"整体否掉**——用户明确表达过"希望 AI 帮我更专注地管理时间"，只是不能变成打分仪表盘。这个张力正是你要处理的。

## 交付

写 `docs/delegate/eval-ai.md`，中文，结论先行，每个结论带证据（文件路径 + 函数名，行号可选）。

1. **总评（≤6 句）**：这份数据现在被压榨到了几成？最大的未被使用的信息是什么（不是"字段不够"，而是"字段里的语义没被用上"）？给一句判断：AI 在这里是必需品还是装饰品。
2. **候选能力（8–12 条）**，每条格式：
   - **一句话用户价值**（用户因此多知道/多做成了什么；说不出来就删掉）
   - **判定：AI / 规则**——能用确定性规则做到的一律标"规则"，并说明规则怎么写（这类条目你仍然列出，但排在后面，因为用户问的是"AI 能做什么"）
   - **输入**：只用已采集数据 + 已有用户输入（手记、标记、项目规则、筛选）；如果必须新增用户输入，写清"一次点选/一句话"，不收表单
   - **输出位置与形态**：hero / 脊柱 / 右栏 / 列表 / 周电影 / 海报 / 放映 / HUD / 检索 / 设置 / 导出；是"草稿待确认"还是"只读展示"（涉及模型输出的，必须是草稿 + 用户确认，这是 ADR 0005 的口径）
   - **为什么模板做不到**：指到具体函数，说明它输出的是"固定句式"还是"真的读懂了这一天"
   - **幻觉与错误如何无害**：越界、编造时间、编造项目名时，界面和落盘各自怎么兜住
   - **成本**：每次调用喂多少 token 量级、延迟量级、要不要用户手动点
   - **工作量**：S / M / L
3. **聚焦回答这四个子问题**（用户点名要的，每条 3–8 行，给结论不要罗列）：
   a. **日评语 / 周评语**：现在模板化的 `judge()` / 周评语，换成模型真的会更好吗？好在哪、风险在哪？"AI 写一句评语"和"模板写一句评语"用户能不能分辨出来、值不值这次网络调用？
   b. **专注管理**：在不做 KPI 的前提下，"帮用户更专注地管理时间"具体能落成什么形态？给 2–3 个具体形态（写清是放映前、回看时、还是第二天早上），并明确说哪些形态会滑向效率仪表盘、为什么必须砍掉。
   c. **语义检索 / 提问**：把"检索窗口标题"升级成"问这一天/这一周"（例如"上周三下午我在改什么"）值不值？如果值，输入是什么、输出落哪、怎么防止模型编造不存在的镜头。
   d. **项目/故事线的自动化**：现在故事线要用户写关键词规则。模型除了"给候选词"还能怎么帮？会不会让用户失去对"我的项目叫什么"的控制权？
4. **推荐顺序**：只给 3 条，按"用户价值 ÷ 工作量"排序，每条一行理由；并给"如果 v4 只做一件事"的答案。
5. **明确不建议做**（尤其是"看起来像 AI 功能"但其实是模板换皮、或者会破坏确定性/隐私的）：一句话一条理由。
6. **旧结论对照表**：`ai-brainstorm-product.md` 里已有的候选，哪些你认可、哪些你认为现在证据不足、哪些你已经否掉——用三行表格说清，避免重复提议。
