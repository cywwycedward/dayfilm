# Dayfilm v4 裁决：读关系，而不是增加记录

**选 A。版本主题定为「故事的连续性」（Continuity）。**

v1 到现在，Dayfilm 已经解决了如何记录一天、如何观看一天、如何把一天制作成电影的问题。v4 应该解决的是：**如何理解一天，以及如何接着昨天继续。**

这不是再增加一种数据展示方式，而是改变已有数据的用途。

## 01 / 版本主线与取舍

## A · 读关系

(v4 主线)

上一集、镜头后续、中场休息、检索对齐与命中理由。

---

**B · 采集与统计修正**  部分立即修复，其余下一步

锁屏误报立即修复；拆分剪辑计数纳入 v4 基础修正；窗口几何留到 v4.1。

---

**C · 光签名**  不做

为装饰性收益改变产品的根本隐私承诺，不划算。

---

**D · AI 手记草稿**  以后独立验证

保留为唯一 AI 实验，但不承担 v4 的成败。

选 A 的理由是，Dayfilm 目前已经拥有足够丰富的原材料，却还主要在按时间和项目两个维度消费它们。

窗口几何能让镜头更丰富，截图能让剧照更真实，AI 能让文字更自然，但只有关系分析能让用户从已有记录中得到此前不知道的东西。

而且它上线当天就能作用于尚在保留期内的历史数据，不需要等待新数据积累。

B 中的锁屏误报属于必须修复的缺陷，不算版本新功能；跨应用与应用内剪辑应该拆开，但不要直接把前者等同于分心，也不要声称解决了 2 秒采样漏记的问题。

## 02 / 截图：永久否决可读截图，光签名也砍掉

我同意永久否决可读截图，但不同意把光签名作为折中方案保留下来。

| 记录内容      | 裁决   | 理由              |
| --------- | ---- | --------------- |
| 可读截图      | 永久否决 | 改变产品的隐私性质       |
| 32×18 光签名 | 不做   | 仍需捕获像素，收益主要是装饰  |
| 窗口几何      | v4.1 | 增加真实、可解释的窗口形态信息 |
| 应用语义构图    | 推荐   | 不接触屏幕像素，兼容历史数据  |
| 声音状态      | 暂不做  | 尚无足够有价值的消费场景    |
| 更高频采样     | 暂不做  | 先修正已有统计的解释方式    |

**「不截屏」比「截了屏但不保存」更有品牌价值。** 不应该为了让剧照好看一点，放弃一句如此干净、容易理解的产品承诺。

### 不碰像素，怎样接近真实画面感？

把现有的合成剧照升级成「语义剧照」：不还原用户看见的内容，而是用真实元数据决定画面构图。

**代码编辑器**

侧栏、编辑区、真实文件标题

**浏览器**

地址栏轮廓、页面结构、真实页面标题

**终端**

命令行视觉节奏、等宽字体

**设计工具**

抽象画板、工具面板、项目标题

语义剧照构图示意：所有内部结构均为抽象模板，不代表实际窗口内容。

现有剧照只是换颜色，下一代剧照可以换构图。等窗口几何加入后，再让前台窗口的占屏比例、位置和显示器参与构图，但不虚构其他窗口的位置。

不能伪造代码、聊天内容、网页正文和真实操作。保留「合成剧照」这一准确称谓。

**追求辨识度，而不是逼真度。** 用户一眼认出自己当时在哪个应用、哪个文档里，就已经达到了唤起记忆的目的。

## 03 / AI：只赌手记草稿，而且给它设退出机制

完全同意不替换日评语和周评语。

Dayfilm 应该把三种文字的作者身份分清楚：

| 内容      | 作者 | 职责          |
| ------- | -- | ----------- |
| 每日／每周评语 | 规则 | 指认发生了什么     |
| 手记草稿    | AI | 尝试把事实组织成一句话 |
| 导演手记    | 用户 | 决定这一天意味着什么  |

AI 不应该成为 Dayfilm 的评论员，而应该成为用户的场记助手。

### 失败判据

建议用 20 个不同类型的真实记录日做一次本地、人工验收，同时放一个纯规则生成的单句摘要作为对照。

事实准确率

# 100%

首次生成校验通过率

# ≥90%

---

愿意直接或轻微修改后保存

# ≥60%

相比规则摘要更愿意采用

# ≥70%

以上是我建议的产品验收门槛，不是已测得的数据。无需增加线上埋点。

任一项未达标，只允许一次针对性调整；第二轮仍未达标就砍掉手记生成入口。

同时重新审查现有 AI 故事线候选：如果也不能稳定提供规则之外的增量价值，就连同模型通道一起移除。

保留纯规则评语、手写导演手记和本地故事线。已被用户采用的手记不受影响。

模型功能不应该因为已经投入开发成本，就永久占据设置面板的一块空间。

选择「上一集」先做，是因为 Dayfilm 此前绝大部分功能都服务于回顾，而它第一次让历史数据直接服务于下一次行动。

精确匹配只能说明上次出现过哪个窗口、哪个标题，不能推断任务完成进度。守住这个边界。

### 第四条：「惯用蒙太奇」

发现用户反复出现的跨应用工作序列，而不是统计用户切换了多少次。

惯用蒙太奇 / MONTAGE

这组窗口转场在过去几天反复出现。

周二 10:42 · 周三 14:08 · 今日 09:36

它和现有「反复」发现的区别在于，不再只识别两个窗口之间的来回切换，而是识别完整的多窗口序列，并允许用户回看实际发生过的片段。

它可能揭示一个非常重要的事实：**高频剪辑并不必然意味着注意力破碎，有时恰恰是一个完整的工作流程。**

这也是 Dayfilm 区别于传统时间管理软件的机会。别人试图减少切换次数，Dayfilm 帮助用户理解切换本身。

## 最终产品定位

Dayfilm 不应该成为一个知道用户越来越多的软件，而应该成为一个越来越懂得利用已有记录的软件。
