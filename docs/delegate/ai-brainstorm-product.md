# Dayfilm × AI：产品价值与叙事能力

只回答一个问题：**哪些 AI 能力是现有确定性规则做不到的，而且值得让用户每天/每周看到。**

## 0. 结论

1. **产品缺的不是语气，是名词。** 现有三套文字（`judge()`、`buildWeekVerdict`、`pickNarration`）已经把"怎么说"做到了很高的下限，但句子里没有一个名词来自窗口标题。用户看完仍不知道"今天在做什么"。
2. **模型在这份数据上唯一不可替代的能力，是把标题里的名词读出来、归到一起、写成一句人话。** 分类、聚类、统计、检索都有更稳的确定性解法；把它们叫 AI 是给规则换说法。
3. **值得先做的只有两个位置：C2 镜头一句话，C1 今日剧情线。** C2 是原子，C1 是句子；C2 先做是为了校准和铺路，C1 才是产品答案。如果只能保留一个用户可见的功能，保留 C1。
4. **所有 AI 输出必须是冻结的附件，不是渲染期调用。** 生成只在用户显式动作时发生，结果带输入指纹落盘；渲染永远读文件。这样"同一份数据任何时候渲染一致"不被破坏，模型缺失时产品仍然完整。
5. **不做的清单和要做的一样重要。** 语义检索、活动类型分布、自动花絮判断、AI 周评语重写、情绪/效率评分，见 §6。

工作量口径：**S ≤ 2 天，M 3–5 天，L > 1 周**；按现有代码结构估算，不含产品评审与真机验收。

## 1. 先划清"AI"的边界

判定线只有一句：

> **把一句话里所有来自标题的专有名词删掉，如果剩下的部分 `judge()` 或 `buildWeekVerdict` 已经能生成，它就是模板，不是 AI。**

对照现有代码：

- `judge()` 的 note 是"最长的一个镜头是 X 的 N 分钟。"（`src/main/reel/rules.ts:31-37`）。删掉 X 和 N，剩下的句式是固定的。
- `buildWeekVerdict` 取变化最大的两条指标拼句（`src/renderer/src/lib/week-film.ts:466-582`）。删掉数字，剩下的还是同一套比较句。
- `pickNarration` 是 5 个优先级分支（`src/renderer/src/lib/narration.ts:28-54`），中段镜头的退路是"停留 N 分钟。"（同文件第 52 行）。删掉 N，什么都没剩。

反过来，"上午在 dayfilm 的 EDL 时间码上"删掉 dayfilm/EDL 就什么都不剩——**这才是模型该去的地方**。这条线同时是验收条件：任何候选通不过，就不要做。

## 2. 三条硬约束，产品层怎么读

### 2.1 不联网决定了模型只能放在哪里

证据：渲染层 CSP 是 `default-src 'self'`，没有 `connect-src`（`src/renderer/index.html:6`）；`installNetworkGuard()` 在打包后 `allowLoopback=false`（`src/main/index.ts:514-519`）；本地判定是纯函数 `isLocalRequest()`（`src/main/security/index.ts:96-107`）。

所以"界面直连模型"直接出局。可行通道只有四条：

| 通道 | 是什么 | 产品代价 | 适用 |
| --- | --- | --- | --- |
| **无模型** | 模板 + 槽位 + 确定性实体抽取 | 0 体积、0 网络、100% 可断言；说得出"是什么"，说不出"像人话的概括" | **默认，必须能独立交付** |
| **用户自备 `.gguf` 侧车** | 独立子进程，stdio 行 JSON，零 socket | 用户要自己准备 0.4–1 GB 模型文件；冷启 2–4 秒、生成 10–45 秒（工程评估，见 `docs/delegate/ai-brainstorm-engineering.md` R3） | opt-in 高质量出口 |
| **本机 `127.0.0.1` 推理服务** | 主进程直连 Ollama / LM Studio | 质量最好、成本最低；但 `PRODUCT.md` 的"不联网"必须改成"不访问互联网；可选连接本机推理服务（默认关闭）"，并增加一个可审计的主进程网络出口（同 R4） | opt-in |
| **用户外带 digest** | 应用导出脱敏 JSON/Markdown，用户粘到自己的 AI，再把 JSON 导回 | 多一步手动操作；标题确实离开本机，隐私边界要逐项展示 | **只做探针和 power-user 出口，不做主路径** |

结论：**候选必须先在"无模型"通道上成立；模型只是把最后一层名词写得更像人话。** 一个功能如果离开模型就什么都不剩，它不该进默认路径。

### 2.2 确定性不是"不要 AI"，是"AI 不能出现在渲染路径"

证据：`PRODUCT.md` 写着"同一份数据在任何尺寸、任何时间渲染结果一致（不引入随机）"；`docs/specs/dayfilm-v1.2.md:32` 与 `docs/specs/dayfilm-v1.4.md:24` 都明确"不调用任何模型"；ADR 0004 也规定周评语确定性生成。

可行的做法是**生成与渲染分离**：

- 新增 `%APPDATA%\dayfilm\ai.json`，照 `notes.json` 的 tmp + rename 写入（`src/main/notes/index.ts:92-98`），每天一条：`{ inputDigest, promptVersion, model, text, evidence, createdAt }`。
- `inputDigest` 由当天的 `(scene.start, scene.end, title)` 哈希算出；不匹配时显示"数据已变，需重跑"，**绝不自动重跑**。
- 生成只由用户显式动作触发（点"生成"），不放进 `onSample`（`src/main/index.ts:410-412`）、不放进 `DayCache.rollup`（`src/main/reel/cache.ts:62-66`）、不放进每 2 秒的 tick。
- 渲染只读已存文本；没有 artifact 就显示确定性骨架，不显示"正在生成"。

C4/C8 会碰 v1.2/v1.4 的"不调用模型"。改法不是删掉这句，而是改成：**默认由模板生成；模型结果只在用户显式生成后作为附加行显示，且冻结。** 原句的意图（不做效率/情绪判断、不让渲染依赖模型）保持不变。

### 2.3 体积和内存不允许模型常驻

实测基线：便携版单 exe 约 76–78 MB（`docs/operations/delivery-verification.md:20` 记录 v1.0.0 为 76.3 MB；同批工程评估记录 v2.6.0 为 78.3 MB）；常驻 RSS 249–254 MB / 预算 300 MB；冷启动 630–930 ms（`docs/operations/perf-report.md`）。便携版每次启动自解压到 `%TEMP%`（`docs/operations/run.md:31`；`electron-builder.yml:28-35` target: portable）。

因此：**模型不入包、不常驻、不阻塞启动。** 生成只能是异步的后台动作，UI 必须接受"点一下，等几秒到几十秒，好了再显示"；"打开即看"的路径上零模型。

## 3. 数据事实：唯一语义是标题，而它正在被扔掉

- 采样只有四个字段：`t`、`exe`、`title`、`idleMs`（`src/shared/types.ts:3-11`）。标题上限 512 字（`src/main/redact/index.ts:5`）。
- 镜头的身份是 `exe + title`：`sameWindow` 把标题变化当成新镜头（`src/main/reel/aggregate.ts:59`）。一次在 Code 里连续改 8 个文件的两小时，通常会变成 8 个左右的镜头、7 次左右的"剪辑"（短于 3 秒的切换会被丢掉；`aggregate.ts:90`、`aggregate.ts:157`）。
- 这不是 bug，是电影语言的单位选择；但它意味着**"剪辑数"里有一部分是标题噪声，不是注意力切换**。内容层不能用"合并镜头"去偷偷改这个数，只能另起一层。
- 聚合层随后把标题从结论里扔掉：`DayRollup.topApps` 只按 `exe` 汇总（`aggregate.ts:102-107`），`judge()` 只吃 `cutRate` 和 `longest`（`rules.ts:31-37`），`DayRollup` 里没有任何 title 派生字段（`src/shared/types.ts:50-69`）。
- 标题在落盘前已经过脱敏：`redactSample()` 只按关键词命中，命中就整条替换成 `[已隐藏]`（`src/main/redact/index.ts:8-30`；调用点在 `src/main/ingest/index.ts:35-36`）。空标题、纯应用名（未打开会话的微信/Telegram）、浏览器新标签页也真实存在。

**结论：内容层不是"模板写得不够好"，是"不存在"。** 任何内容功能都必须先处理空标题、`[已隐藏]` 和纯应用名；模型不能把"未命名窗口"编成一个故事。

## 4. 候选

脊柱与右栏不承接任何 AI 文案：脊柱是时间几何（`src/renderer/src/lib/spine.ts`），右栏是数字与放映控制（`DESIGN.md` 的层次 3–4）；把句子塞进去会抢题材的唯一视觉重点。HUD 同理，见 §6。

### C1 今日剧情线

**价值**：一天结束时，不用翻镜头表就知道这卷胶片在讲什么——"上午在 dayfilm 的 EDL 时间码上，下午被三场会切开，傍晚回到同一个文件收尾"。用户多知道的是**今天的内容主线**，不是时长分布。

**验收问句**：用户看完能说出"今天主要在 X 上，中间被 Y 打断，晚上回到 Z"。

**规则为什么做不到**：`judge()` 只吃 `(cutRate, longest)`，输出 4 档 label 和一句"最长的一个镜头是 X 的 N 分钟"（`src/main/reel/rules.ts:31-37`）；`DayRollup` 里与内容有关的聚合只有 `topApps: { exe, seconds }`（`src/main/reel/aggregate.ts:102-107`）；`renderScreenplay` 是一行一镜（`src/main/reel/index.ts:229-259`）；`pickNarration` 的 5 个分支只判断 id 是否等于最长/首/尾/密集窗（`src/renderer/src/lib/narration.ts:28-54`）。这些函数没有一个从 `scene.title` 里提取内容（`renderScreenplay` 只是把原文抄进一行）；`judge()` 和 `pickNarration` 连标题都不碰。"今天干了什么"在数据通路上不存在。

**输入**：当天全部 `scenes`（`exe/title/start/end/mark`）+ 可选 `note` + `projects`。不需要新采集。

**落点**：hero，`#verdict`（`src/renderer/index.html:104`）下一行 `hero__logline`；展开 3 条证据；Markdown 剧本的题材段后加一段（`renderScreenplay`）；可选进开场字幕卡。

**最小形态**：固定 3 段（上午/下午/晚上，按当天最长的两次中场休息切；不足两次就按活跃时长三等分），每段 ≤24 字；只允许六个动词：看/写/改/查/聊/等；每段必须引用 1–3 个真实镜头键 `(date, start)`；没有 artifact 时显示确定性骨架（"上午 Code 47 分 · Chrome 12 分 · 会 40 分"）。一行，不新增卡片，不占栅格。

**幻觉与失败风险**：模型会编因果（"因为要交稿所以…"）和编完成态（"修好了 EDL"其实只是打开了 issue）。无害化四件事：禁因果连词；禁"完成/修复/搞定"；每个专有名词必须是某条证据标题的子串；证据可点回胶片。AI 行永远在 `judge()` 下面，不替换它；`inputDigest` 变了只标"需重跑"。

**工作量**：M（冻结层 + digest + 校验 + hero + 剧本各一处）。

### C2 镜头一句话

**价值**：列表、EDL、PDF、放映里每一镜从"dayfilm - Visual Studio Code"变成"改 dayfilm 的 EDL 时间码"。用户多知道的是**这一镜在干什么**；一屏就能看出这 40 分钟是在改时间码，还是在读 spec。

**验收问句**：用户能在列表里指出"这 40 分钟是在改时间码，不是在读文档"。

**规则为什么做不到**：`buildRow` 直接显示 `scene.title`（`src/renderer/src/app.ts:836-888`）；EDL 的 clip name 直接拼 `exe - title`（`src/main/edl/index.ts:49-53`）；PDF 镜头表的标题列也是原文（`src/main/pdf/index.ts:53-61`）；`matchProject` 只能把标题映射到用户手写的项目名（`src/shared/projects.ts:15-28`）。规则能剥掉 " - Visual Studio Code" 后缀，但剥完只剩 "dayfilm"；"在改时间码"这层信息只在标题的自然语言片段里（例如 "dayfilm.ts — EDL timecode"），需要读懂。

**输入**：单镜 `title + exe + seconds`；可选同标题的相邻镜头作为上下文。

**落点**：列表标题格（`buildRow`）；放映 `#projectionTitle`（`index.html:292`）；EDL clip name；PDF 镜头表；海报镜头 caption（`src/renderer/src/lib/poster.ts:414`）。

**最小形态**：每条 ≤12 字；每天只给"时长前 50 的唯一标题"打标签，其余回落原文；缓存键是原始标题，不是 `scene.id`（同一标题只算一次）；原始标题保留在 hover/详情里；一个设置开关；不写存储。**标签必须在加载当天数据时一起算好，不能按行异步取**——列表是虚拟滚动的，`listSignature` 只认首尾和长度（`app.ts:912-934`），异步补标签不会触发重绘。

**幻觉与失败风险**：把 "Pull Requests" 说成"在合并代码"（其实只是在看列表），或把私聊对象名写进标签。无害化：动词只用看/写/改/查/聊；不出现"完成/合并/修复"这类断言；不引入标题里没有的名词；原始标题永远可见；开关默认关闭，用户自己开。

**工作量**：S（只做渲染层标签表）/ M（若在主进程接模型与缓存）。

### C3 故事线名字

**价值**：周电影的故事线从 "Code / Chrome / Terminal" 变成 "dayfilm / 客户报表 / 论文"，不用手写关键词。用户多知道的是**这一周在讲哪条线**，而不是在讲哪些软件。

**验收问句**：用户能说出"这周主线换过一次，周三被报表抢走"。

**规则为什么做不到**：`matchProject` 要求用户手写 `terms`，按规则顺序**首命中即返回**，且只做 `title.includes(term) || exe.includes(term)`（`src/shared/projects.ts:15-28`）；没有规则时 `mainLineOf` 直接退化成按 `exe` 汇总（`src/renderer/src/lib/week-film.ts:182-196`）；`buildStoryline` 的行名就是项目名或 exe（`week-film.ts:280-346`）；`badgesFor` 只能标"同一主线连续 ≥3 天"（`week-film.ts:348-388`）。

必须承认：**这条 70% 是字符串工程，不是模型。** 剥 ` - Visual Studio Code` / ` — Google Chrome`、去未读计数 `(3)`、去路径前缀、按 `· / — - |` 切首段、抽 `#\d+`、抽文件名、按频次排序——这些都能确定性做。模型只补两件事：中文自然语言标题的簇归并、给簇起一个 ≤12 字的名字。

**输入**：近 30 天全部 `title`（已脱敏）+ 现有 `projects`；可选用户改名。

**落点**：设置 → 项目规则（`#projectCards`，`index.html:336`）的"从标题生成草案"；周电影 `#storyline` 行名与 `#weekArcs`（`app.ts` 的 `renderStory()` / `renderArcs()`）；剧本项目行（`renderScreenplay`）。

**最小形态**：只产草案表：`名字 / 2–3 个精确 terms / 5 条样例标题 / 覆盖天数`。用户逐条勾选才写 `settings.projects`，**不自动应用**。无模型时用该簇出现最多的归一化词做名字，功能照常可用。

**幻觉与失败风险**：错误归并会污染周统计和项目时长。无害化：草案不落盘；terms 是精确子串，用户能预判命中范围；每条草案带样例；一键撤销本次导入；现有规则优先，不被草案覆盖。

**工作量**：M（确定性实体层 + 草案 UI + 设置写入）。

### C4 周剧情句

**价值**：周评语从"最长镜头比上周多 12 分钟"多出一句剧情："周一、周二在 dayfilm 的 EDL 上；周三换到客户报表；周五回到 dayfilm 收尾。" 用户多知道的是**这一周的剧情怎么走**，不是三个数字的增减。

**验收问句**：用户能说出"这周的剧情怎么走的"。

**规则为什么做不到**：`buildWeekVerdict` 只比较 longest / cutRate / active 三个数，取变化最大的两条拼句（`src/renderer/src/lib/week-film.ts:466-582`）；`badgesFor` 只能标单天的"换戏"和"连续 ≥3 天"（`week-film.ts:348-388`）；`buildColumns` 只标"切/回"（`week-film.ts:251-278`）。整条链路没有任何跨天的主语名词。

**输入**：7 天 `acts`（`mainLine/longest/cuts`）+ 每天 top 3 标题。

**落点**：周电影 `#weekVerdict`（`index.html:261`）现有数值句**下面**一行；证据进 `#weekEvidence`；不替换数值句。

**最小形态**：≤2 句；句式限制为"周 N 主线是 L" / "周 N 换到 L" / "周 N 回到 L"；每天最多 1 个事件；没有换戏就不写第二句；每个主语必须是真实的 `mainLine` 或标题子串；模型只负责选哪两个事件构成剧情、给主语一个可读的名字。

**幻觉与失败风险**：叙事天然编因果，"被报表抢走"暗示意图。无害化：禁因果连词；只写"换到/回到/连续"；AI 句永远在数值句下面；可关；`inputDigest` 变了标"需重跑"；任一从句的证据缺失就整句丢弃。

**工作量**：M（依赖 C3 的实体层和 C1 的证据契约）。

### C5 前情提要

**价值**：打开今天，先看到"上次在这条线上停在 11月21日 17:40 的 dayfilm.ts"。用户多知道的是**跨天的连续性**：这件事上次做到哪。

**验收问句**：用户能说出"这件事我上次做到哪"。

**规则为什么做不到**：日视图只加载当天（`loadDate`，`src/renderer/src/app.ts:1476` 起）；`DayRollup` 没有跨天引用；`matchProject` 只在当天聚合（`src/shared/projects.ts:31-43`）；周电影只在周内（`week-film.ts`）。"上次出现"是确定性可算的；"当时在做什么"要读标题。

**输入**：当天/近 30 天同项目或同实体的镜头。

**落点**：hero 的 `#projectTotals`（`index.html:229`）下方一行；或 `#highlights`（`index.html:169`）第一张卡；点击跳到那天。

**最小形态**：一行 ≤30 字：`上次：11/21 17:40 · dayfilm.ts · 42 分钟`；只匹配精确实体（项目名、文件名、issue 号），不做模糊；不猜"完成没完成"。

**幻觉与失败风险**：同一个文件名不等于同一件事。无害化：只显示日期、时间、原始标题、时长，让用户自己判断；不写因果；不做模糊匹配；没有精确命中就不显示。

**工作量**：S。

### C6 片名

**价值**：1600×1000 的海报上，大标题位置现在永远是 4 个题材词之一；一个片名让海报可带走、可分享。用户多知道的是**这一天的一句话概括**，不是"快切"这个分类。

**验收问句**：用户能说出"这一天叫这个"。

**规则为什么做不到**：`judge()` 的 label 只有 4 个取值（`src/main/reel/rules.ts:31-37`）；海报的文案来自题材 + 数字 + 用户手记（`src/renderer/src/lib/poster.ts:303` 的 genre、`:326` 的 verdict note），没有任何命名环节。

**输入**：当天 top 标题 + 题材 + 可选手记。

**落点**：海报主题菜单旁"片名：三选一"；选定进 PNG。

**最小形态**：3 个 ≤8 字候选，可选可编辑；不选就用题材；候选禁止"奋斗/热爱/高效/充实"这类词；不自动选。

**幻觉与失败风险**：俗套、文艺腔。无害化：用户自己选；可编辑；不选就回退；不写进任何数据。

**工作量**：S。

---

### C7 导演阐述

**价值**：导出的 Markdown / PDF 剧本不只是一张镜头表，开头有一段 120–180 字的导演阐述，说清这一天在做什么。用户多知道的是**这一天的意义**，而不是又一份日志。

**验收问句**：用户觉得"这份导出值得读，不只是日志"。

**规则为什么做不到**：`renderScreenplay` 是汇总 + 一行一镜（`src/main/reel/index.ts:229-259`）；`judge()` 只有一句 note；没有任何跨镜头的段落生成。

**输入**：当天 scenes + note + projects +（可选）C1 artifact。

**落点**：Markdown 剧本的汇总段之后；PDF 第一页；导出菜单里的"附导演阐述（AI 草稿）"复选框。

**最小形态**：3 句：这一天以什么为中心、有一次什么转折、以一个什么事实收尾；≤180 字；每句挂 1–2 个镜头证据；固定标注"AI 草稿"；下方数据表原样保留；没有 artifact 就不生成这一节。

**幻觉与失败风险**：**这是最危险的位置**——导出的文档看起来最权威，编造的事实最容易被当成真的。无害化：只允许 3 句结构；禁因果、禁完成态、禁评价；每个专有名词必须来自证据标题；脚注编号可回查；用户勾选才附加；删掉这一节不影响其它导出。

**工作量**：M。

---

### C8 放映旁白的内容层

**价值**：放映中段绝大多数镜头只有一句"停留 N 分钟。"（`src/renderer/src/lib/narration.ts:52`）；内容层能让它说"今天第三次回到同一个 PR 页面"。用户多知道的是**这一镜和之前的关系**。

**验收问句**：用户觉得"放映中段不再是同一句"。

**规则为什么做不到**：`pickNarration` 只有 5 个分支、靠 id 相等判断（`narration.ts:28-54`），看不到同标题的历史，也读不出标题里的对象。注意：**"第几次 / 间隔多久"是规则能算的，AI 只该负责给这个对象命名**（"同一个 PR 页面" vs "同一个文件"）。

**输入**：当前镜头 + 同标题/同实体的当天与近 7 天历史。

**落点**：放映态字幕 `#projectionSubtitleText`（`index.html:287`）；其余 4 个分支不动。

**最小形态**：只替换最后的 fallback 分支；≤24 字；无形容词；每 10 镜最多 3 句 AI，其余保持原句；默认关闭，开了才用。

**幻觉与失败风险**：低（一闪而过、不落记录）。无害化：长度上限；无形容词；关掉后完全回到现状；不引用没有出现过的对象。

**工作量**：S。

---

### C9 检索的查询改写

**价值**："上次改时间码那会儿"能定位到那天的 Code 镜头。用户多知道的是**东西还在，只是换了个说法**。

**验收问句**：用户能用一句话找到那天的镜头。

**规则为什么做不到**：`searchScenes` 是 `title.toLowerCase().includes(needle)`，按开始时间倒序截 200 条，无评分、无同义、无分词（`src/main/reel/index.ts:202-212`）；主进程只查最近 7 天（`src/main/index.ts:51`、`src/main/index.ts:333-338`）。标题是 "dayfilm - Visual Studio Code"，"改时间码"必然 0 命中。

**输入**：查询串 + 最近 7 天 scenes。

**落点**：顶栏搜索（`#search`，`index.html:23`）+ 列表结果。

**最小形态**：**先确定性**——别名表（EDL ↔ 时间码 ↔ timecode）、多词 AND、剥 app 后缀后匹配文件名；只有在 0 命中时，才让模型把查询改写成 3 条候选关键词，结果仍由真实 `includes` 产出。

**幻觉与失败风险**：编造的命中用户很难识破，检索错等于找不到东西。无害化：AI 只改查询、不产结果；显示"改写为：X"并允许编辑；每条结果显示命中的是哪个词；不建向量索引。

**工作量**：S（改写）/ L（真正的向量索引，不建议，见 §6）。

---

### C10 手记草稿

**价值**：手记框旁边一个"起个头"，用户改两个词就能存。它不增加知识，只降低起笔成本——这也是它排最后的原因。

**验收问句**：用户觉得"这句是我写的，不是机器写的"。

**规则为什么做不到**：手记本来只有用户能写（`src/main/notes/index.ts:7` 的 200 字上限，`clampNote` 在 `:16-18`）；`judge().note` 和 `buildWeekVerdict` 都是模板。只有当草稿里出现标题里的专有名词时，它才不是模板；而这依赖 C1。

**输入**：C1 artifact + 当天数字；可选用户已有的半句话。

**落点**：hero 手记框（`#note`，`index.html:139`）右下角。

**最小形态**：只在 C1 已生成时显示按钮；点一下填入**可编辑**的一句 ≤40 字；不自动保存；`clampNote` 的 200 字上限照旧（`notes/index.ts:16-18`）；C1 不存在就不显示按钮。

**幻觉与失败风险**：这是最容易退化成模板的一格，还会鼓励用户不写。判定线见 §8：删掉专有名词后如果与 `judge().note` 同构，就不要做。

**工作量**：S。

## 5. 排序与推荐

| 序 | 候选 | 用户因此多知道什么 | 规则替代度 | 幻觉代价 | 复用面 | 工作量 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | **C2 镜头一句话** | 这一镜在干什么 | 部分（能剥后缀，读不懂内容） | 低 | 列表 / EDL / PDF / 放映 / 海报 | S |
| 2 | **C1 今日剧情线** | 今天在做什么 | 不能 | 中高 | hero / 剧本 / 手记 | M |
| 3 | C3 故事线名字 | 这一周在讲哪条线 | 70% 能 | 中 | 设置 / 周电影 / 剧本 | M |
| 4 | C5 前情提要 | 上次停在哪 | 部分 | 中 | hero / 列表 | S |
| 5 | C6 片名 | 这一天叫什么 | 不能 | 低 | 海报 | S |
| 6 | C8 旁白内容层 | 中段镜头和之前的关系 | 部分 | 低 | 放映 | S |
| 7 | C4 周剧情句 | 这周剧情怎么走 | 不能 | 高 | 周电影 | M |
| 8 | C7 导演阐述 | 这一天的意义 | 不能 | 高 | 导出 | M |
| 9 | C9 检索改写 | 换个说法也能找到 | 部分 | 中高 | 检索 | S |
| 10 | C10 手记草稿 | 手记起个头 | 大多能（模板） | 高 | hero | S |

### 推荐先做的两个：C2 → C1

它们不是两个独立功能，是同一条内容层的两层：C2 是输入，C1 是出口。

**为什么是 C2 先**：它是内容层最小的单位，五个面直接吃它（列表、EDL、PDF、放映、海报）；它只读不写，风险最低；它同时是一次校准探针——如果模型在这份真实标题语料上连 12 字的镜头标签都写不出有信息量的名词，C1 一定失败。C2 还是 C1 的词表：C1 的句子由 C2 的标签组成，先有原子才有句子。

**为什么是 C1 第二**：它是唯一回答产品现在答不出的问题的候选。`judge()` 已经把"今天像什么"答完了（而且答得不错），"今天到底在干什么"一个字都没有。C1 也是 C4/C7/C10 的前置；没有 C1，后面三个只能写模板。

**为什么不是 C3**：它是七成字符串工程，价值真实但不需要模型；应该作为 C1 的实体层和设置页的草案 UI 单独排期，不要把它算成 AI 的主要赌注。它还有写路径（`settings.projects`），爆炸半径比 C1/C2 大。

**为什么不是 C4**：它是价值很高但风险最高的一条：周的叙事天然编因果，而用户一周只看一次，一次编造就会毁掉信任。等 C1 的证据契约在真实数据上跑过几周，再让 C4 引用同样的证据。

**为什么不是 C5/C6/C8**：C5 是 C1 的连续性子集；C6 是纯装饰；C8 只替换一个 fallback 分支。它们都值得做，但都不该排在 C1 前面。

**为什么不是 C7**：导出的文档最像"权威事实"，也是幻觉代价最大的位置；放在最后，且默认不附加。

**为什么不是 C9/C10**：检索的频率低，确定性别名能覆盖大部分；手记草稿大概率是模板。两条都不该占用第一版。

### 如果只能做一个

**做 C1，但把 C2 作为它的第一个里程碑。** C2 单独发布只是"更好看的标签"；C1 才是产品从"你怎么过的"跨到"你在干什么"的那一步。C2 不单独作为用户可见功能发布，只作为 C1 的输入层和校准探针。

## 6. 明确不建议做

| 不建议 | 一句话理由 |
| --- | --- |
| 应用内直连云端 API | 与 README 第一句和 `PRODUCT.md` 的"不联网"正面冲突，且主进程 `fetch` 不受网络守卫约束，等于拿旧文案骗用户。 |
| 首启下载模型 / 把模型打进 exe | 便携版每次启动自解压到 `%TEMP%`，76–78 MB 已经要解压一次，再加几百 MB 是灾难。 |
| 本地向量索引 / embedding 语义检索 | 30 天语料、唯一标题几千条，别名 + 子串 + 多词 AND 先做；embedding 要付模型、运行时、原生 ABI、便携解压、索引重建五笔债。 |
| 活动类型分布图（写/读/查/聊/会） | `exe` 白名单能覆盖 3–4 类，做成饼图就是 `PRODUCT.md` 明说不要的效率仪表盘。 |
| AI 重写 `judge()` / `buildWeekVerdict` | 这两个函数已经把"取最大变化 + 带证据"做到了模板的最优解；重写只会更慢更飘，ADR 0004 也明确不调用模型。 |
| 自动花絮 / 正片判断 | 模型判断"这段时间算不算"是价值判断，`SceneMark` 没有理由字段（`src/shared/types.ts:20-34`），误判直接改统计。 |
| 情绪 / 专注 / 效率评分 | 数据只有窗口标题，推不出情绪；这类输出会被用户当真，伤害真实。 |
| 实时 HUD AI 摘要 | 每 2 秒采样、渲染期调用，直接破坏确定性；而且用户此刻知道自己在干什么。 |
| 自动写手记 | `notes.json` 是产品里唯一的人声（`src/main/notes/index.ts`）；机器写进去，这个功能就废了。 |
| AI 脱敏 | 假阴性制造假安全，模型还要先看到敏感文本；先把邮箱、手机号、URL token 的确定性规则补齐。 |
| 截图 / 多模态 | 产品第一句就是"不采集屏幕内容"；截图会把已脱敏的标题重新变成原文。 |
| 不确认就写 `settings.projects` 的自动聚类 | 一次错并就污染周统计与项目时长；只能出草案、逐条确认、可撤销。 |
| 周报 / 效率周报 | ADR 0004 已否决；"把七天统计相加就能得到"的功能不做。 |

## 7. 专题：窗口标题里的语义能用到哪一步

| 方向 | 裁决 | 证据与理由 |
| --- | --- | --- |
| **活动类型分类** | **能做，但不单独做** | `topApps` 只有 exe 维度（`src/main/reel/aggregate.ts:102-107`），这是硬缺口；但六类里有 3–4 类能被 exe 白名单 + 标题关键词覆盖。模型增量在长尾和"读 vs 写"。产出若是分布图，就是仪表盘；只作为 C1 句子里一个词槽（"在读文档"）。 |
| **项目归一化** | **做，主体是确定性** | `matchProject` 的 `includes` + 首命中 + 用户手写 `terms` 是真实痛点（`src/shared/projects.ts:15-28`）；没有规则时周主线退化成 exe（`src/renderer/src/lib/week-film.ts:182-196`）。解法七成是字符串处理，模型只补中文自然语言标题的归并与命名；最终必须落成 `terms` 才兼容现有统计。 |
| **意图摘要** | **做，但改叫内容摘要** | 数据里没有"意图"，只有上下文；叫"意图"会诱导模型编动机。就是 C1：说清"在什么上、被什么打断、回到什么"，不说"为什么"。 |
| **语义检索** | **先不做** | `searchScenes` 只做子串（`src/main/reel/index.ts:202-212`），但 30 天语料里的查询多是"我记得那个东西"，不是"意思相近的句子"；别名表 + 多词 AND + 剥后缀能覆盖大部分。先测真实查询的 0 命中率，低于 15% 就永远不做向量索引。 |
| **自动命名故事线** | **做，作为 C3 的副产品** | 单独做价值不够（只是一个显示名），成本也几乎为零（一次 ≤12 字输出）；用现有项目名做 ID，不另建一套实体系统。 |

三条必须提前说的覆盖事实：

1. **标题不总有语义。** 空标题、`[已隐藏]`、纯应用名（未打开会话的微信/Telegram）、浏览器新标签页，都必须进"未知"，不能编。
2. **标题里有第三方数据。** 邮件主题、私聊对象、客户名都可能是标题。本地模型没问题；外带通道必须在导出前显示"将发送 N 条标题，M 条已脱敏，K 个应用被排除"，并默认排除邮件和 IM。现有 `redactSample` 只按关键词命中（`src/main/redact/index.ts:8-30`），不认客户名。
3. **中文标题没有空格。** 归一化要处理全半角、`—`/`-`/`·`/`|`、未读计数 `(3)`、路径前缀、`*` 脏标记；这些是规则，不是模型。

一个反例值得记住：`matchProject` 是首命中即返回，所以"AI 归并成一条故事线"和"用户写三个关键词"之间差的不是智力，是**排序与覆盖**。任何 AI 方案最终都要落成 `terms` 才不破坏兼容——这项能力的天花板是工程，不是模型。

## 8. 专题："AI 导演评语 / 手记草稿"是 AI 还是模板

**结论：已有的周评语不要 AI 化，手记草稿不要单独做。** 周评语的数字句（`buildWeekVerdict`）保持模板；唯一值得模型写的是 C1 日剧情线，C4 是它在周视图的附加行，C10 是它的一句话版本。谁离开 C1，谁就退回模板。

判定线见 §1。按这条线逐个看：

| 产物 | 判定 | 依据 |
| --- | --- | --- |
| `judge().note` | **模板，保持** | `src/main/reel/rules.ts:31-37`：一句话、一个事实；模型只会让它变慢、变飘。 |
| `buildWeekVerdict` | **模板，保持，别重写** | `src/renderer/src/lib/week-film.ts:466-582`：取变化最大的两条 + delta + evidence 表，已经是最优解；ADR 0004 明确不调用模型。 |
| C4 周剧情句 | **可以是 AI，但只在引用真实主线/日期时** | `badgesFor` 只能标单天（`week-film.ts:348-388`），跨天的"事件选择"确实需要模型；句式仍是模板，模型负责选事件和命名。 |
| C10 手记草稿 | **多半是模板** | 输入只有数字时，输出必然等价于 `judge().note`；只有 C1 存在、能引用"EDL 时间码"这类对象时才成立，这就是它排最后的原因。 |
| C8 放映旁白 | **一半 AI** | `pickNarration` 的 5 个分支已经覆盖最长/最密/首尾（`narration.ts:28-54`）；计数是规则，命名才是模型。 |
| C1 日剧情线 | **是 AI** | 它要在三个时段里选名词、压缩成三句；`judge()` 和 `buildWeekVerdict` 都不做这件事。 |

一句话：**评语里没有专有名词，就是模板；有专有名词，才值得请模型。专有名词来自 C2/C3 的实体层，不来自模型。**

## 9. 落地形状：最小契约

不要为每个候选发明一套机制。共用一套：

```text
%APPDATA%\dayfilm\ai.json
{
  "version": 1,
  "days": {
    "2026-11-23": {
      "inputDigest": "sha256:...",
      "promptVersion": "daylog/v1",
      "model": "qwen2.5-1.5b-instruct-q4",
      "text": "上午在 dayfilm 的 EDL 时间码上；下午被三场会切开；傍晚回到同一个文件收尾。",
      "evidence": ["2026-11-23:1795392000000", "2026-11-23:1795413600000"],
      "createdAt": 1795420000000
    }
  }
}
```

日级或按天缓存的产物（C1/C4/C5/C7/C8/C10）共用这个文件；C2 的标题标签、C3 的草案各自是一张表，但同样带 `inputDigest` 与冻结标记。原则相同，键不同。

- **证据键用 `(date, start)`，不用 `Scene.id`。** `Scene.id` 是 `${date}-${序号}`（`src/main/reel/aggregate.ts:140`），会随新数据变动；`marks.json` 已经因为同样的原因用开始时刻做键（`src/main/marks/index.ts:9`）。
- **校验五条**：长度在范围内；每个专有名词是某条证据标题的子串；每个证据键能在当天 `scenes` 里找到；禁因果连词（因为/所以/导致/终于/说明）；禁完成态与评价词（完成/修复/搞定/高效/专注/焦虑）。任一不满足，整条 artifact 丢弃，退回骨架。
- **状态只有三种**：`未生成`（不显示或显示骨架）、`已生成`（显示正文 + 证据）、`过期`（灰字"数据已变，需重跑"，不自动跑）。没有"正在生成"的常驻占位。
- **降级**：模型缺失/超时/输出不合 schema → 骨架 + 一行灰字；不弹窗、不 toast、不阻塞导出、不进 `LiveState`。
- **隐私**：本地通道不发送任何数据；外带通道在导出前逐项展示发送内容与脱敏统计；不做遥测。日志只记通道名和错误类型，不记标题（`src/main/index.ts:300-310` 已有同样的克制）。

## 10. 先证伪：五个探针

1. **C2 探针**：取真实 7 天、50 条标题，让候选模型写 12 字标签。人工数"含标题里真实名词、且不是纯应用名"的比例；低于 60% 就停止 C1 的模型路径，只交付规则版（剥后缀 + 文件名），不要用"模型不行就换模板"糊过去。
2. **C1 探针**：同一份数据生成 5 天的三句话，删掉所有专有名词，与 `judge().note` + 骨架对比；如果读起来同构，说明它只是模板，砍掉。
3. **证据探针**：用第 9 节的五条校验跑一遍，统计丢弃率；高于 40% 说明输入太薄或契约太严，先修输入，不要先看 UI。
4. **用户探针**：给 5 个真实用户看 5 天的 C1，只问一句"你知道了什么以前不知道的"；如果答案全是数字或"今天很忙"，这个功能没有产品价值。
5. **检索探针**：收集 20 条真实查询，只做别名 + 多词 AND + 剥后缀，统计 0 命中率；低于 15% 就永远不做语义检索。
