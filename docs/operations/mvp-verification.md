# MVP 验证记录

第一里程碑的逐条验收结果。验收时间 2026-11-22，环境 Windows 11 + Node.js 22.19.0 + Electron 33。核对方式是主 Agent 在真实构建产物上通过 DevTools 协议读取界面与 IPC 返回、检查进程与落盘文件，不只依赖实现者的单元测试。

## 结论

R1–R8 通过。R9 的剧本渲染通过单测，保存对话框未做自动点击，属于部分验证。规格 R1.3 已按实际实现调整（见下）。

## 与规格的偏差

**R1.3 自我窗口。** 规格原写"记录为剪辑中"，实现为：自身窗口采样照常落盘，但不进入胶片、汇总与检索，胶片上表现为无素材区；实时条仍按实际前台窗口显示。已把规格改成该行为。理由：MVP 的契约（`Scene.kind`）只有镜头与中场休息两种，为"剪辑中"新增第三种状态要同时改主进程、界面与测试；该状态对用户价值有限，留到第二里程碑评估。

## 过程中修掉的问题

1. 采集子进程在宿主被强杀后的残留风险：增加 `-ParentPid` 判活与 `taskkill /T` 进程树清理。修前实测宿主消失后 6 秒内自行退出（靠写管道失败），修后下一轮采样前即退出。
2. 汇总区"活跃时长 0 分"与"镜头 1"自相矛盾：分钟数改为正数下限 1 分钟，与主进程剧本口径一致。
3. 空档文案"摄影机未运行"不准确（自身窗口时段也会留空）：改为"没有采样"。
4. 胶片空白区像渲染失败：加低对比度点阵底纹。
5. 1440×900 下底部出现横向滚动条：修掉溢出容器。

## 未验证与已知限制

- 保存对话框的真实点击路径（R9）。
- 断电、而非强杀，之后的恢复。
- 含引号、反斜杠与中文的窗口标题在真实采集链路上的往返（本次真实采样只覆盖 ASCII 标题；链路本身强制 UTF-8）。
- 仅在 Dayfilm 运行时采样，没有开机自启与托盘常驻。
- 单日镜头数很多时的列表性能，未做虚拟滚动。
