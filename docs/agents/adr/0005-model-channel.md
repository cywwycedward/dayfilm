# ADR 0005：模型通道用 OpenAI 兼容端点，显式 opt-in

- 状态：已采纳（v3.0）
- 日期：2026-11-23
- 相关：[v3 功能规格](../../specs/dayfilm-v3.md)、[方向裁决](../../delegate/ai-proposal.md)、[外部裁决](../../delegate/gpt-answer-9.md)

## 背景

Dayfilm 的"智能"文字全是模板：`judge()` 的题材点评、`pickNarration()` 的放映字幕、`buildWeekVerdict()` 的周评语。数据只有 4 个字段（时间戳、进程名、标题、空闲毫秒），标题里塞着文件名、issue 号、PR 标题、会议名。

外部裁决（`docs/delegate/gpt-answer-9.md`）的结论是：先把**确定性**的语义层做出来（故事线候选、剪辑发现、检索增强），生成式模型只在用户显式触发时作为补充，不进渲染路径。产品侧另有要求：模型配置要按 coding agent 的习惯来做——给接口地址、API key、模型名就能调用，复用成熟库，不自己实现传输与重试。

## 决策

1. **协议**：OpenAI 兼容的 `chat/completions`。接口地址（`https://api.openai.com/v1`、`http://127.0.0.1:11434/v1`、任何兼容网关）、模型名、可选 API key 三项即可工作。
2. **实现**：复用官方 `openai` SDK（传输、超时、错误类型都由它处理），不手写 fetch 与重试。SDK 进 devDependencies 由 Vite 打进主进程产物，运行时不依赖 `node_modules`（保持便携版单 exe 的结构）。
3. **位置**：只在主进程（`src/main/ai`）。渲染层 CSP 不变，界面只多一个 `invoke`。
4. **触发**：只有用户点「测试连接」或「用模型补充」才发请求；启动、采样、翻日、渲染路径上零请求。
5. **产出**：模型只给"故事线候选"，且候选必须能回到真实镜头（命中数由本地数据数出来）。不落盘、不冻结、不改现有统计；确认才写 `settings.projects`。
6. **降级**：超时 20 秒、失败/格式不符一律退回确定性候选，界面一行灰字说明原因，不弹窗。

## 备选与被否的理由

| 备选 | 否决理由 |
| --- | --- |
| 本地 GGUF 侧车（用户自备 `.gguf`） | 要新增一个二进制与子进程治理；便携版每次启动解压整包，只适合做"没有任何现成服务时的兜底"，不进默认路径。先不上。 |
| 连本机 Ollama / LM Studio | 协议与 OpenAI 兼容，正好被本决策覆盖：用户把 `baseUrl` 填成 `127.0.0.1` 就是本地模型，不需要另一套代码。 |
| 自己写 HTTP 客户端 | 超时、SSE、错误分类、重试都要自己维护；官方 SDK 是成熟实现，体积在打包后约 0.8 MB。 |
| 模型进渲染层 | `sandbox: true` + `default-src 'self'` 没有加载路径，也不该让界面直接碰网络。 |
| 模型写评语/旁白并落盘渲染 | 与 `PRODUCT.md` 的确定性承诺冲突；同一份数据每次渲染必须一致。 |

## 后果

- `PRODUCT.md` 的"不联网"改成"默认零出站请求；模型通道是唯一出口，默认关闭、只由用户点按钮触发"。这是产品承诺的一次明确改写，需要 R15.5 的审计口径同步：`src/main/ai` 是唯一允许建连接的模块，且必须落在用户填写的 `ai.baseUrl` 上。
- `apiKey` 以明文存 `settings.json`，与 coding agent 的配置文件同一口径；界面不回显，只显示是否已设置。
- 主进程产物从约 0.2 MB 涨到约 1.06 MB；打包后的便携版 exe 实测从 78.27 MB 到 78.42 MB（+0.15 MB，`dist/Dayfilm-3.0.0-portable.exe`），压缩把 SDK 吃掉了。
- 生成结果**不承诺可复现**（跨模型版本会漂），所以只作为"候选"出现，不进入任何会被渲染或导出的产物。
- 模型不可用时产品完整：三个 v3 功能都有纯规则版本，模型只是候选的第二来源。
