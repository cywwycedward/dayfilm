# ADR 0004 下一步方向：一周电影

- 状态：已采纳
- 日期：2026-11-22
- 来源：外部裁决（ChatGPT，项目 `not-my-app`），提问与回答留档在 `docs/delegate/ask-gpt-1.txt` 与 `docs/delegate/gpt-answer-1.md`

## 背景

v1.1 之后用户反馈"功能还是太少"。候选方向有五个：跨天与周报、长期回忆、主动仪式感、专注承诺与目标、社交分享。本地证据无法判断哪个方向能带来真实价值而不是统计堆砌。

## 决策

做 A 方向的强化形态——**一周电影**，而不是"周报"。约束是：把七天统计相加就能得到的东西不做。

优先做三件事，顺序如下：

1. 七日叙事弧（主线如何延续、转移、回归）
2. 周导演评语（与上周对比的一句话结论，可展开证据）
3. 本周精选（5–7 个关键场景，可点击回放到当天）

## 理由

- 一天有镜头但没有故事；一周才出现情节（启动、推进、被打断、回到主线）。单日题材捕捉不到这个层次。
- 项目标签、剪辑密度、回放、手记这些已有能力在周维度第一次产生跨时间意义，不需要新增采样。
- "看看今天发生了什么"是偶发需求，"这一周变成了什么样"更接近习惯。
- 其它方向：长期回忆需要数月数据才有价值；主动提醒是分发机制不是内容；专注承诺会把产品推向效率工具而不是观察工具；分享在隐私优先的产品里不宜作为核心。

## 后果

- 周模式成为独立的一层视图，复用现有 `getDay` 数据，不新增存储与采样维度。
- 评语必须确定性生成，不引入模型调用，也不做效率评价或情绪推断。
- 后续接入"周一回顾"通知时，入口接在这套周视图上，而不是另做一套提醒系统。
