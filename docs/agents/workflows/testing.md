# 测试工作流

## 适用条件

测试设计、补充覆盖、专项验收或排查不稳定用例是主要交付目标。功能开发、缺陷修复和重构中的常规验证由相应工作流完成。

## 上下文依赖

核对目标行为、验收条件或接口约束，以及现有用例、夹具、测试入口和结果判据。涉及特定 QGIS、provider 或运行配置时，补查实际测试环境。[功能规格索引](../../specs/INDEX.md) · [工程文档索引](../../engineering/INDEX.md)

## 执行步骤

1. **确定要观察的行为和判据。** 说明测试要识别哪种错误，以及通过什么入口和结果观察它。用规格、已知结果或独立推导确定预期。
2. **选择足以观察目标行为的验证环境。** 优先复用现有场景、测试数据和替身。`npm run check` 覆盖静态和规范检查，行为测试按目标选择 pytest 或验收入口。需要验证真实 provider、任务调度或工程副作用时，先核对 pytest 的覆盖范围，再按需使用无头验收。验收 QGIS Desktop 窗口交互时，可用 `agent-desktop` 取得实际界面证据。
3. **核验判据并运行测试。** 新增或修改用例时，用已知反例、修复前失败或其他证据核对用例能识别目标错误。测试先行时，可用 `tdd` 在已约定的行为边界逐项验证用例先失败、实现后通过。先运行目标用例，再按影响范围运行相关回归。
4. **判读结果。** 区分产品失败、环境问题、跳过和未运行。无头验收退出码为 `0` 时，仍需核对相关用例的逐项结果。

## 完成条件

目标行为、测试入口和判据可以对应。交付可定位的命令、版本、环境和结果，说明新增覆盖、实际执行范围以及仍缺的证据。
