# 评审工作流

## 适用条件

受托评审代码差异、PR 或交付证据，或依项目规范开展独立评审。实施中的常规自检由相应工作流完成。

## 上下文依赖

核对评审委托、目标差异或交付物、已确认的要求和适用的工程约定。[功能规格索引](../../specs/INDEX.md) · [工程文档索引](../../engineering/INDEX.md)

- 公共契约、架构边界或其他项目约束受到影响时，补查对应领域的权威资料。[项目文档索引](../../INDEX.md)
- 评审对象或要求来自 Issue 或 PR 时，核对来源及相关记录。[Issue 跟踪配置](../issue-tracker.md)

## 执行步骤

1. **固定范围和版本。** 记录目标及所审查的版本。评审变更时，记录比较基线和实际纳入的差异。评审工作区时，明确暂存、未暂存和纳入评审的未跟踪文件。评审验收证据时，核对记录对应的实现版本、环境和场景。
2. **分别核对规范和规格。** 按有效的工程规则及契约检查实现。逐项对照已确认的要求，查找缺失、偏离或超出范围的行为。规格证据不足时，继续核对工程规范和回归风险，并指出无法判定的要求。可使用 `code-review` 评审有明确比较基线的已提交差异。
3. **写出可复核的发现。** 按影响列出发现，每项记录文件或证据位置、触发条件、实际后果和判断依据。指出已有验证的覆盖范围和关键证据缺口。仅受托评审时保持只读，结果交给获授权的实现者处理。[多 Agent 协作规范](../policies/collaboration.md)
4. **针对更新版本复审。** 有复审任务时，核对原问题的处理结果，以及本轮修订新影响的行为。将结论对应到实际复审版本。

## 完成条件

结论与评审版本、范围、适用规则和依据对应。报告发现及影响，并说明无法核对的范围或未解决事项。未发现问题时，交代实际检查范围和验证限制。
