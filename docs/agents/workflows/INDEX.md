# Agent 工作流索引

按任务的主要交付目标选择工作流。实现任务中的常规验证、交付自检和随改动更新文档在主工作流中完成。测试、评审或文档变更本身是交付目标时，选择相应的专项流程。

| 任务 | 工作流 | 交付依据 |
| --- | --- | --- |
| 新增功能或改变已确认的功能行为 | [功能开发](feature.md) | 已确认的技术方案、架构及功能验收证据。 |
| 定位或修复执行异常和回归 | [缺陷修复](bugfix.md) | 预期与实际的差异、原因证据及适用的修复验证。 |
| 专门设计、补充或验证测试 | [测试](testing.md) | 测试覆盖的行为、独立判据和实际结果。 |
| 评审代码变更、PR 或交付证据 | [评审](review.md) | 固定范围及版本下的发现、依据和评审限制。 |
| 在保持既有行为的前提下调整结构 | [重构](refactor.md) | 可定位的结构收益和可对照的行为证据。 |
| 专项更新、整理、迁移或重组项目文档 | [文档变更](docs-change.md) | 权威内容、有效入口及事实和引用的核验结果。 |

目标改变时，重新选择适用流程。影响范围扩大或关键资料有冲突时，查阅上下文管理规范。需要判断是否请用户参与时，查阅人类注意力规范。交付时按沟通规范说明验证结果和遗留事项。[上下文管理规范](../policies/context.md) · [人类注意力规范](../policies/attention.md) · [沟通规范](../policies/communication.md)
