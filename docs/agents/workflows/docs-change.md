# 文档变更工作流

## 适用条件

以更新、整理、迁移或重组项目文档为主要交付目标。随代码同步相关文档时，在原工作流按文档治理规范完成。

## 上下文依赖

核对读者任务、现行入口、受影响的索引和引用，以及相关内容的权威来源。[项目文档索引](../../INDEX.md) · [项目文档治理规范](../policies/documentation.md) · [文档编写与修改规范](../policies/writing.md)

- 修改 Agent 规则或流程时，补查受影响的规则和任务路径。[Agent 规则索引](../INDEX.md)
- 涉及权威归属迁移、退役或授权边界时，按适用规范确定评审和授权要求。[人类注意力规范](../policies/attention.md)

## 执行步骤

1. **确定读者要完成的任务。** 从实际使用入口查找相关内容，核对现行职责、重复和冲突，划定此次变更范围。
2. **核对事实和归属。** 用有效规格或已确认决策核对预期，用实现、配置、测试或运行证据核对现状，按版本和状态引用历史资料。逐项确定权威落点和治理动作。生成文档需要调整时，先核对生成源和规则。[资料缺失或冲突的处理](../policies/context.md#资料缺失或冲突)
3. **修改内容并同步入口。** 按目标状态修改权威正文，更新受影响的索引、入链和退役入口。涉及历史决策时核对状态和替代关系。编写 Agent 指令或任务入口时可用 `writing-for-agents`。变更领域术语或记录架构决策时可用 `domain-modeling`，按项目约定定位对应文档。[领域文档](../domain.md)
4. **按读者路径验证。** 从现行入口找到更新后的内容，核对关键陈述、示例、标题锚点和交叉引用。运行适用的项目检查，并结合人工走查覆盖检查工具未验证的内容。Agent 工作流变更按受影响的任务情景走查路由和完成条件。[项目命令](../../../package.json) · [功能规格索引](../../specs/INDEX.md)

## 完成条件

权威落点清楚，读者能从现行入口找到有效资料。受影响的索引、引用及退役状态已核对，关键陈述和示例有可追溯的依据。交付时说明实际完成的检查和待核验事项。
