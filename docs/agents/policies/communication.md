# Agent 沟通规范

本规范适用于同一开发项目内发给用户或其他 Agent 的自然语言消息。

- 判断是否发消息、何时发或多久更新一次时，查阅[人类注意力规范](attention.md)。
- 分配任务或组织协作时，查阅[多 Agent 协作规范](collaboration.md)。
- 编写文档、代码注释或 Docstring 时，查阅[文档编写与修改规范](writing.md)。

## 所有消息

- **准确优先。** 按实际观察和核对结果陈述事实、已执行的操作和验证结果。明确标出推断、计划和未验证事项，说明具体限制及其影响。
- **按接收者组织。** 开头给出答案、结果或请求。简单消息用短句，复杂消息按需要用分段、列表或短标题。在保证准确的前提下，遵循用户指定的语言、格式和详略。保留影响理解、决策或后续工作的条件、证据和风险。
- **保留技术原文。** 路径、标识符、字段、命令、参数、配置项和引用的报错或日志片段使用实际拼写。

## 发给用户

默认使用自然的中文，按中文开发者的习惯选词。用直接的动词和具体的对象。常用英文术语如 API、Bug、Commit、PR、Token 可以保留，成熟的中文术语直接使用。

用短句和具体因果关系说清发生了什么、有什么影响、可以怎么处理。沿用用户熟悉的术语。需要解释新术语时，结合当前代码或任务直接说明，只有能帮助理解时才用比喻。用户要求深入时，再展开原理、边界、取舍、实现和验证方式。

| 消息目的 | 内容顺序 |
| --- | --- |
| 答疑 | 直接回答，再给关键依据。 |
| 说明改动 | 写清改了哪里、解决了什么。验证影响结论时，给出实际状态。 |
| 分析故障 | 说明观察到的现象，标明推测原因，优先给出有价值的排查方向。 |
| 比较方案 | 先给建议，再说明最重要的取舍。 |
| 解释概念 | 结合具体场景说明用途。 |

**说明验证和风险。** 区分已修改、已测试、合理推测和尚未确认的事项。数据丢失、兼容性或安全等实质风险要写清触发条件、实际影响和可行的处理办法。结论的确定程度以证据为准。

**纠正错误。** 说清错误和修正。确需道歉时，简短说一次。删去重复道歉、自我辩解、空泛免责声明、套话、问题复述和无关过程。

### 例句

- 已改动，未验证。“代码改好了，还没跑测试，暂时不能确认结果。”
- 兼容性影响。“参数从 `token` 改成了 `accessToken`，原来的调用代码也需要改。”
- 解释概念。“这里会暂存查询结果，重复请求就不用再查数据库。”

## 发给其他 Agent

使用能准确传达技术信息的语言，保持同一条消息内用语一致。写明具体模块、文件或行为，避免指代含混。保留接收者核对或接续所需的上下文，日志优先摘录关键片段。

| 消息目的 | 需要交代的内容 |
| --- | --- |
| 发出请求 | 目标、相关范围、关键约束和预期产出。已有明确上下文时省略重复内容。 |
| 报告结果或改动 | 实际结论、改动内容、位置和影响。提及代码时优先给出文件路径和符号名，精确定位时补充行号或片段。 |
| 报告验证 | 执行的命令或测试、实际结果和覆盖范围。明确标注未运行的相关验证。 |
| 报告失败或阻塞 | 具体现象、关键错误、已知条件和未解决的问题。 |
| 交接未完成事项 | 说明剩余工作及相关位置。有剩余工作时才写待办。 |

**标明来源。** 区分实际观察、有依据的推断和待验证的假设。区分用户的明确要求、任务约束、Agent 自行采用的假设和提出的建议。引用代码、日志、网页或工具输出时注明来源。指令按实际发出者归属，事实按核对结果陈述。仍有未知项时，说清内容及其影响。

**让证据可追溯。** 使用实际路径、符号名、测试名、命令或简短错误片段，让接收者能够定位并核对。信息密度随任务复杂度调整，保留关键约束、证据、边界和失败细节。

### 例句

| 场景 | 表达 |
| --- | --- |
| 发出请求 | 检查 `auth/login.ts` 的空 Token 处理。保留现有 API 返回字段。交付修改点和测试结果。 |
| 报告结果 | 在 `auth/login.ts` 增加空 Token 判断。`auth.test.ts` 的登录相关 6 个用例通过。尚未做端到端验证。 |
| 报告推断 | 请求超时且连接等待数升高。连接池可能已经耗尽。尚未检查连接泄漏。 |
| 报告失败 | 运行 `npm test -- auth.test.ts` 后有 1 个用例失败。预期 401，实际 500，原因待确认。 |
| 说明来源 | 用户要求降低超时率。将重试次数设为 5 是 Agent 的提议，尚未得到用户确认。 |

## 发出前检查

- 实际完成的工作和验证结果有依据，推断与未确认项已标明。
- 用户能直接看出答案、必要依据和实际影响。其他 Agent 能定位工作、核对证据并接续任务。只检查当前接收者适用的要求。
- 删去重复内容后，消息仍保留接收者判断或行动所需的约束、证据、风险和未知项。
