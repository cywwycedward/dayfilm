# 项目文档治理规范

先检查文档影响，再决定是否治理。关注需要长期复用的项目知识及其查阅入口，沿用项目现有的文档结构和管理约定。自动生成的文档存在问题时，先判断是否需要治理生成源或生成规则。临时记录和局部实现变化影响持久知识时，检查对应的长期文档。

## 何时检查

| 时点 | 检查内容 |
| --- | --- |
| 相关任务开始时 | 当前文档是否足以支持任务，相关接口、模块和约定是否有可查阅的权威来源。 |
| 发现设计或实现变化时 | 变化是否影响长期有效的行为、契约、架构、配置或操作方式。 |
| 交付前 | 按实际改动和已确认决策复查，找出遗漏的文档更新和受影响的引用。 |
| 开展文档专项整理时 | 在约定范围内核对文档归属、内容和入口，判断是否存在重复、冲突、过时或查找困难。 |

从任务影响到的主题和已知入口开始。复用已经核实的结论，只在新增影响或发现关联问题时扩大查阅范围。

## 何时治理

当任务授权覆盖治理范围，且符合以下任一条件时，启动治理。

- **持久知识变化。** 未来的开发、使用、部署或维护仍要依赖的信息发生了变化。
- **权威来源缺失。** 需要长期复用的信息尚无明确、合适的归属。
- **文档存在实际问题。** 相关内容重复、冲突、过时，或读者难以找到有效来源。

检查后未发现上述情况，即可结束。例如，局部实现重构后，接口、行为和长期约定均未变化，相关文档仍然有效，只需完成影响检查。

## 选择治理动作

通过[项目文档索引](../../INDEX.md)和对应领域的局部索引，确认文档的职责、内容边界和权威来源。优先维护现有权威来源，其他文档通过引用指向它。需要判断规格、设计和实际行为之间的冲突时，查阅[上下文管理规范](context.md)。

| 动作 | 触发条件 |
| --- | --- |
| 更新 | 已有权威来源可以承载该知识，且其内容、索引或引用需要修正。 |
| 新增 | 知识需要长期保存或复用，现有文档均无合适归属，且能说明新文档的职责和入口。 |
| 拆分 | 一份文档承担多个可独立维护的职责，现有组织使信息难以定位或维护。 |
| 合并 | 多份文档职责重叠，分别维护造成了重复或冲突，且合并后可以保留有效信息。 |
| 废弃 | 内容已失效，仍需在原查阅位置提示读者，并在有替代来源时指向它。 |
| 归档 | 内容适合移出现行入口，仍有历史、审计或决策追溯价值。 |
| 删除 | 已核对引用、唯一记录和留存要求，确认无需保留，且授权明确覆盖删除。 |

涉及权威归属迁移、文档退役或其他高影响变更时，按[人类注意力规范](attention.md)判断是否需要另行批准。按实际影响评估改名、移动和移除入口。ADR、重要决策记录、审计证据、合规资料和发布历史原则上保留。

变更 Agent 规则时，评估它对相关 Policy、Workflow 和任务执行的影响。涉及授权、安全或审批边界时，按影响级别完成独立审查。放宽权限、安全或测试约束须取得明确的人工批准。

## 索引与引用

- **分层索引。** `docs/` 内统一用 `INDEX.md` 承载目录说明与导航。项目总索引说明直接子目录的职责、查阅时机，并链接各子目录的索引。局部索引登记本级文档及子目录入口，说明文档职责、应包含的内容、边界和查阅时机。存在必要前置或条件依赖时，一并标明。
- **引用目标。** 引用一组资料时，链接到负责该范围的索引。引用具体规则、事实或操作说明时，直接链接到权威文档，必要时定位到相关标题。已知权威位置时可直接查阅。
- **链接写法。** 仓库内引用使用相对 Markdown 链接，路径和标题锚点与实际目标一致。仓库外的权威资料使用对应入口链接，并在所属索引写明检索方式。
- **同步变更。** 新增、移动、改名或退役文档时，核对并更新所在层的索引和受影响的引用。目录职责或入口发生变化时，同步上一级索引。

## 何时算完成

执行治理后，按变更范围核对结果。

- 权威来源明确。预期行为的说明与已确认的设计或契约一致，现状说明与可核实的实现证据一致。
- 受影响的索引、入口和引用已经同步，读者能找到有效来源。
- 退役文档的状态和原因清楚，有替代来源时能找到对应入口。

优先使用项目已有的检查工具。关键冲突、核验缺口或所需授权仍未解决时，将受影响的事项列为待处理。

执行专项整理时，查阅[文档变更工作流](../workflows/docs-change.md)。修改正文时，查阅[文档编写与修改规范](writing.md)。
