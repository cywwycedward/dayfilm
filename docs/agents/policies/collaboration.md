# 多 Agent 协作规范

委派前确定任务边界、写入归属和交付证据。主 Agent 负责整体范围、依赖协调和最终验收。子 Agent 在分配的范围内工作，发现范围变化或阻塞时先向主 Agent 汇报。

## 委派与隔离

1. **交代任务。** 在当前授权范围内写清目标、验收条件、依赖的规格或决策、起始版本、允许改动的文件或模块，以及预期交付。需要等上游任务确认接口或约束时，明确写出开始条件。
2. **分配写入。** 每个共享文件指定一个写入责任人。只有写入范围互不重叠、所依赖的接口已明确的任务可以并行实施。存在共享改动或前置依赖时，指定责任人统一修改，或按依赖顺序推进。
3. **确认工作区和交接位置。** 有并行写入或需要隔离变更时，使用独立 worktree 或运行工具支持的等效隔离方式。同一任务的后续实现和修复沿用其工作区及上下文。派发前确认接收者能访问所需资料和结果位置。涉及分支或 worktree 的创建、集成与清理时，遵守仓库的 [Git 分支与 worktree 规范](../../engineering/git-workflow.md) 和写入归属约定（见[开发约定](../../engineering/conventions.md)），并在交付说明里写明分支与工作区。

## 接续与集成

| 阶段 | 责任和完成条件 |
| --- | --- |
| 实施 | 实现 Agent 按约定边界交付，指明改动版本、受影响的接口和验证结果。 |
| 独立评审 | 需要独立评审时，由未参与该改动的 Agent 从规格、基线和实际差异出发，独立核对证据。评审工作区保持只读，发现的问题写入评审记录。 |
| 回应与复审 | 由原实现者接续处理评审发现，逐项说明改动或保留理由。影响验收的问题处理后，基于更新版本重新核对。 |
| 集成 | 由获得授权的责任人核对目标分支、已核验版本、未决评审事项及验证要求。发现需要改变实现的冲突时，交回责任人处理。集成后在目标工作区执行适用的检查，并记录实际结果。 |

## 交接与阻塞

- 接手前查阅上一份相关交接，确认版本、依赖和待解决问题。交付时让接收者能定位改动和验证证据，并区分实际完成、未验证和尚待处理的事项。消息表达按[沟通规范](communication.md)。
- 复杂任务用可访问的交接文件保存细节，消息只传结论和位置。消息渠道不可用时，通过约定位置交接结果。本地交接记录可放在 `docs/delegate/`。需要长期复用的约束或决策，按[文档治理规范](documentation.md)归入对应的权威来源。
- 任务受阻或发现超出范围的改动时，向主 Agent 说明受影响的工作、已有证据及需要的决定。由主 Agent 协调冲突、调整分工，并按[人类注意力规范](attention.md)判断是否需要用户介入。

使用 Herdr 启动 Agent、收发消息、等待结果或清理会话时，查阅 `herdr-core`。需要在用户的 Herdr 窗口中显示会话时，查阅 `herdr-app`。
