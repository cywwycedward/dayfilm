# API 与消息契约

## 适用场景

接口供另一个组件、客户端或外部团队消费时，先明确他们能依赖的请求、响应、事件和错误行为。将契约维护为可校验的文本，按需用 Archify 制作[时序图](13-uml-sequence.md)或[事件流图](17-event-flow.md)。

## 契约内容

- **HTTP API。** 用工具链支持的 OpenAPI 版本，写清路径、方法、操作 ID、参数、请求与响应 Schema、状态码、鉴权及示例。
- **异步 API。** 用工具链支持的 AsyncAPI 版本，写清通道、操作、消息及 Schema。
- **兼容性。** 说明版本与弃用策略。按操作需要定义失败语义、超时及重试责任。有外部副作用且允许重试时，定义幂等规则。

## 编写步骤

1. 明确消费方用例，确定资源、操作或事件名。
2. 定义请求、成功响应、错误响应及安全约束。
3. 校验契约，按需生成 Mock 或 SDK，使用契约测试核对实现。

## 示例

订单接口的 `POST /orders` 使用 `placeOrder` 作为操作 ID。请求包含至少一条带产品 ID 和正整数数量的条目。创建成功返回 `201`。库存不足返回 `409`，契约同时说明错误响应结构。

## 完成检查

契约通过所选版本的校验。消费者可据此构造请求、解析成功与失败响应，判断兼容性并编写联调测试。
