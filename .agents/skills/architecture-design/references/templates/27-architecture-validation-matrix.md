# 架构规则与验证矩阵

## 适用场景

把架构视图和 ADR 中的关键约束转成可以在开发、评审或 CI 中执行的检查。

## 建模内容

每条规则记录稳定 ID、约束对象、要求、验证类型、执行依据、触发时机和失败处理。静态检查覆盖源码依赖，契约检查覆盖接口承诺，行为测试覆盖状态、不变量和竞态，运行时检查覆盖实际拓扑和观测要求。需要人工判断的规则注明负责人和复评时机。

## 编写步骤

1. 从权威设计提取约束，并将规则连到对应架构视图或 ADR。
2. 为每条约束选择能直接验证它的检查。可自动化时纳入 CI，按需补充人工审查。
3. 记录失败证据和处理方式。确有豁免时记录适用范围及复评条件。需要讲解验证流程时，可用 Archify 制作配图。

## 示例

| 规则 | 验证方式 | 触发时机与失败处理 |
| --- | --- | --- |
| `ARCH-01` 领域模块的依赖限定在允许的层 | 按允许的依赖方向检查源码导入 | PR 验证。发现违规时定位引入依赖的文件 |
| `PAY-01` 重复回调只产生一条有效记账记录 | 并发回调集成测试 | 支付相关变更。失败时检查幂等判定与存储约束 |

## 完成检查

每条关键规则都能追到可执行检查或有明确负责人的人工验证。审查者能定位失败证据，判断该检查覆盖的范围。
