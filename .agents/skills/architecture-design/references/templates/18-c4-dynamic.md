# C4 动态视图

## 适用场景

用于说明 C4 静态模型中的元素如何协作完成一个用例。按交互顺序选择 Archify 的 `sequence` 模式，重点是步骤或分支时选择 `workflow` 模式。

## 建模内容

- 以场景名和起止范围限定视图。沿用 C4 静态模型中的系统、容器或组件名称、ID、边界和关系。
- 给交互编号，写清谁对谁做什么。需要详细表达复杂分支或循环时，可用[时序图](13-uml-sequence.md)补充。
- 共同维护静态与动态视图所依赖的模型。要求交付正式 Structurizr 动态视图时，用同一模型的 `dynamic` 定义生成。

## 绘制步骤

1. 从 C4 L2 或 L3 确定场景参与元素。
2. 按发生顺序列出交互，以模型关系和契约校验各步。
3. 用相应场景测试核对行为，发现新元素或新关系时回到静态模型确认。

## 示例

顾客在 `Web App` 提交订单。`Web App` 调用 `Backend API` 中的 `OrderController`，由 `OrderController` 调用 `Orders` 创建订单。`Orders` 请求 `Inventory` 预留库存，再将订单写入 `PostgreSQL`。

## 完成检查

- 每个元素和关系能在同一套 C4 模型中定位。
- 顺序、场景边界和重要分支与相关契约或测试一致。
