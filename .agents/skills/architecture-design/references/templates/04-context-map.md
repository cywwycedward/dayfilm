# DDD 限界上下文图

## 适用场景

判断不同业务模型如何划界和集成，尤其是同一个业务词在不同领域含义各异时。用 Archify 的 `architecture` 表达上下文边界和集成关系。

## 建模内容

每个上下文写清业务职责、模型术语和数据所有权。连线标出上下游的影响方向、提供方和使用方，以及公开契约、事件或翻译层。需要区分集成策略时注明 DDD 模式，如 Partnership、Shared Kernel、Customer/Supplier、Conformist、Anti-Corruption Layer、Open Host Service 或 Published Language。模型边界以业务含义为准，可映射到同一个部署单元。

## 绘制步骤

1. 从业务能力和领域事件识别语义冲突，确定边界和各自的术语表。
2. 标出上下文的所有权及集成策略，分别写明上下游影响和运行时交互。
3. 核对公开契约、跨边界的翻译职责和对应集成测试。

## 示例

`Inventory` 是库存契约的上游提供方，`Orders` 是下游使用方。运行时由 `Orders` 发起库存查询。订单上下文通过防腐层与 `Payments` 集成，翻译支付状态后再用于自己的模型。

## 完成检查

上下文的职责、术语和数据所有权清楚。读者能沿每条跨界关系找到契约、语义翻译以及负责验证的测试。
