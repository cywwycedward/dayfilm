# EventStorming 事件风暴图

## 适用场景

和领域专家梳理复杂业务，发现关键业务规则、上下文候选和待确认问题。用 Archify 的 `workflow` 表达已梳理的事件关系。

## 建模内容

从已经发生的领域事件出发，如 `OrderPlaced`。补充触发它的命令、参与者、外部系统、聚合和策略。沿业务时间线排列，标出争议、未知规则和异常等热点。卡片颜色和符号按工作坊约定，通过图例说明。

## 绘制步骤

1. 邀请领域专家与开发者写出已知业务事件并排序。
2. 沿事件追溯触发命令和参与者，补齐执行业务规则的聚合、在事件之后触发动作的策略和关键异常。
3. 聚类出可能的限界上下文，逐项记录待确认的热点。

## 示例

顾客发出命令 `PlaceOrder`，订单聚合产生 `OrderPlaced`。下单后预留库存的策略发出 `ReserveStock`，库存聚合产生 `StockReserved`。将「库存不足时订单如何处理」标为待确认热点。

## 完成检查

主要事件使用业务语言并表达已经发生的事实。关键事件能追溯到触发条件，领域专家能确认时序和规则，尚未确定的规则在图中可辨认。
