# UML 类图

## 适用场景

用类图设计核心领域对象或复杂代码的静态结构，明确类型职责、持有关系和可替换接口。用 Archify 的 `class` 模式制作图。

## 建模内容

- 为类写明名称和有助于理解职责的属性、操作及不变量。接口用 `«interface»` 标识。
- 按 UML 的语义选择关系。泛化用实线空心三角指向父类，实现用虚线空心三角指向接口。关联可标角色、可导航方向和多重度。依赖用虚线箭头指向被依赖方。
- 聚合用空心菱形，组合用实心菱形。菱形在整体一端。组合用于表达整体对部分的归属和生命周期约束。短期使用关系用依赖表示。

## 绘制步骤

1. 从一个用例找出关键概念，确定职责和不变量。
2. 区分实体、值对象和接口，建立必要关系，标出多重度。
3. 补充承载业务行为的操作，关联验证不变量和类型协作的测试。

## 示例

订单包含一项或多项明细，每项明细属于一个订单。明细随订单生命周期管理，因此两者是组合关系。`SqlOrderRepository` 实现 `OrderRepository` 接口。`Order.cancel()` 承载取消规则。

## 完成检查

- 每个类型的职责能对应到用例。关联、组合、泛化与依赖有各自可解释的依据。
- 多重度符合领域规则。关键操作和不变量有可核对的验证依据。
