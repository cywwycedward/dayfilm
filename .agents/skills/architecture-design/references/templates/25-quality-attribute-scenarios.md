# 质量属性场景表

## 适用场景

把性能、安全、可靠性、可修改性或可扩展性要求写成可观察、可验收的场景。

## 建模内容

用场景表记录六项信息。刺激源是谁，刺激是什么，系统处于何种环境，影响哪个系统部分，系统应如何响应，以及用什么度量验收。

## 编写步骤

1. 把质量目标拆成具体的负载、故障或安全事件。
2. 定义环境、响应和可测量阈值。
3. 指定对应的性能测试、故障测试、安全测试或其他验证方式。需要讲解行为时，可用 Archify 制作配图。

## 示例

| 要素 | 重复支付回调 |
| --- | --- |
| 刺激源 | 外部支付平台 |
| 刺激 | 同一笔支付确认重复发送三次 |
| 环境 | 正常运行，多个应用实例并发接收 |
| 受影响部分 | 回调处理器、订单状态和记账记录 |
| 响应 | 验签并识别重复事件，只执行一次业务状态转换 |
| 响应度量 | 并发测试中仅一条有效记账记录，三次接收均可审计 |

## 完成检查

测试人员能够按表重现场景，并依据明确的阈值判定结果。
