# UML 活动图

## 适用场景

用于整理业务或算法活动的控制流，尤其是判断、并行和汇合。用 Archify 的 `workflow` 模式制作图。涉及跨参与者的消息或流程引擎执行语义时，查阅 [BPMN 业务流程图](15-bpmn-process.md)。

## 建模内容

- 按 UML 语义标明初始节点、动作、决策与合并、Fork 与 Join、最终节点。
- 为决策写明互斥且覆盖可能结果的守卫条件。并行执行分别标明分叉和需要同步时的汇合或等待。
- 需要说明谁负责哪个动作时，用泳道表示职责。

## 绘制步骤

1. 定义活动的起止和完成结果，列出动作及责任方。
2. 写明每个决策的判断条件。对并行活动确认汇合条件。
3. 沿每条路径推演到合法终点，提取对应验收场景。

## 示例

开始后检查库存。库存充足时预留库存，再保存待支付订单。库存不足时拒绝下单并结束。若保存失败，按流程定义释放预留并以失败结束。

## 完成检查

- 所有分支都有可判断的条件和终点。
- 并行、互斥和汇合的含义清楚。正式 UML 交付按 UML 活动节点语义另行核对。
