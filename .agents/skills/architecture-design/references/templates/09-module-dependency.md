# 模块依赖图与 UML 包图

## 适用场景

在设计、重构或架构检查中明确哪些源码模块可以依赖哪些模块。用 Archify 的 `architecture` 表达模块及依赖。使用正式 UML 包图时，按 UML 的包依赖与导入语义标注。

## 建模内容

节点是可映射到仓库位置的模块或包，记录其职责、所有权和公开入口。当前视图中的 `A → B` 表示 A 的源码引用 B。目标视图中的同一方向表示允许 A 引用 B。优先维持单向分层，发现循环时记录原因和治理计划。

## 绘制步骤

1. 从源码目录、构建结构和公开 API 找到模块边界。
2. 分析 `import` 或构建引用，画出依赖方向并与允许的方向核对。
3. 对可检查的边界规则增加 lint 或架构测试，记录实际依赖和目标规则的偏差。

## 示例

`api → application → domain`。适配器所在的 `infrastructure` 可以指向 `application` 和 `domain`。`domain` 的允许依赖中不含 `infrastructure`，由架构检查拦截反向导入。

## 完成检查

所有重要节点都能映射到仓库，连线可用源码引用或目标规则解释。跨模块依赖使用公开入口，循环和不符合规则的实际导入均有明确处理项。
