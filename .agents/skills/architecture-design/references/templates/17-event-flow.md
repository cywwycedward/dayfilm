# 事件流与异步协作图

## 适用场景

用于梳理异步发布、订阅和失败恢复。用 Archify 的 `workflow` 模式表现发布与消费步骤，重点是消息去向时用 `dataflow` 模式。

## 建模内容

- 说明内部领域事件承载的事实及对外集成事件的契约。标出事件所有者、发布方、消费方、方向、topic 或 channel，以及事件名和版本。
- 按中间件和消费端的实际配置写交付与顺序保证。明确去重键、幂等边界、重试条件、死信、重放及观察入口。
- 用 AsyncAPI 或消息 Schema 记录载荷和兼容策略，图链接到同一契约。

## 绘制步骤

1. 找到要跨边界共享的事件，确定所有者、版本与目标通道。
2. 逐个列出订阅者和成功处理结果，补充失败、重试及重放路径。
3. 对照契约和配置检查假设，设计契约测试与重复投递的集成测试。

## 示例

`Orders` 向 `orders.placed` 发布 `OrderPlaced.v1`，`Billing` 和 `Analytics` 分别订阅。假设至少一次投递，`Billing` 用事件 ID 去重，处理多次失败后将事件移至死信队列供排查和重放。

## 完成检查

- 每位消费者能找到正确的事件版本、通道和交付约定。
- 重复、乱序或失败时的处理结果已确定，并能用契约、配置或验证证据核对。
